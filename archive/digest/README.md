# 个人沉淀 · digest/

> **定位**：存放需要**人亲自甄别、过滤、决策**的知识清单。AI 负责生成清单，人负责填写判断。
>
> 这个文件夹是"消化系统"，不是"生产系统"——里面的文件不追求完美，追求的是**你真的看过、想过、决定过**。

---

## 命名规范

```
YYYY-MM-DD_<主题>.md
```

示例：
- `2026-05-16_飞轮复盘沉淀清单.md` — 首份沉淀清单
- `2026-06-01_Sprint回顾沉淀.md` — Sprint 结束时的定期沉淀
- `2026-06-15_新项目冷启动审视.md` — 新项目启动前的知识盘点

## 预期节奏

| 触发场景 | 频率 | 内容 |
|---------|------|------|
| 阶段性复盘（如飞轮分析） | 按需 | 从复盘报告中提取需要人判断的清单 |
| Sprint 结束 | 每 1-2 周 | 微反思汇总 + 规则去留 + 踩坑复盘 |
| 新项目启动 | 按需 | 盘点哪些已有知识可迁移、哪些需要补课 |
| 季度盘点 | 每季度 | 全库扫描：报告分层、Skill 使用率、模式采纳率 |

## 文件状态标记

每份沉淀清单在 frontmatter 中用 `status` 标记进度：

- `pending` — 清单已生成，尚未开始消化
- `in-progress` — 部分项目已甄别
- `done` — 全部项目已甄别，可归档

## 与其他目录的关系

| 目录 | 角色 | 关系 |
|------|------|------|
| `reports/` | 知识生产 | digest 的输入来源——报告中"需要你判断"的部分提取到这里 |
| `PATTERN_LIBRARY.md` | 模式仓库 | digest 中的"模式去留"决策结果回写到 PATTERN_LIBRARY |
| `skills/` | 工具箱 | digest 中的"Skill 使用评估"可能触发 Skill 归档或改进 |
| `sessions/interaction-log/` | 行为数据 | 沟通模式分析也是一种沉淀，但存在 interaction-log 下 |
