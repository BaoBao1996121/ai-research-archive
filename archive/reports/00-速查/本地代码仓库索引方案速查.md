# 本地代码仓库索引方案速查

> 场景：为本地代码仓库（例如 Python/TS/前端混合项目）建立代码索引，让 AI 或人类读代码更快、更准。
> 研究日期：2026-05-22
> 关联报告：R08（大型多仓代码库上下文方案）、R07（代码检索能力实验）

---

## 一句话结论

**推荐组合：Repomix（一次性打包给 AI）+ Zoekt/Sourcebot（持续搜索服务）**。如果你只是偶尔需要让 AI 理解整个项目，Repomix 一行命令搞定；如果你需要持续、高频地在多个仓库间搜索代码，Sourcebot（基于 Zoekt）是自托管最优解。

---

## 定位透镜

### 纵轴 · 演化脉络

代码索引工具经历了三个阶段：

```
阶段 1（2015-2020）：文本搜索引擎
  Zoekt（Google 内部工具开源）、Hound（Etsy）
  ↓ 核心能力：三元组索引 + 正则匹配，极快但无语义

阶段 2（2020-2024）：语义理解层加入
  Sourcegraph + SCIP 协议、bloop（已归档）
  ↓ 核心能力：AST 解析 + 跳转定义 + 引用查找

阶段 3（2024-现在）：AI-Native 代码理解
  Repomix、Sourcebot（Ask Sourcebot）、Aider repo-map
  ↓ 核心能力：把代码打包/索引后直接喂给 LLM 问答
```

### 横轴 · 竞争格局

| 工具 | 定位 | 核心技术 | 开源/付费 | 活跃度 |
|------|------|---------|-----------|--------|
| **Repomix** | 代码打包给 AI | Tree-sitter 压缩 + 格式化输出 | MIT, 25.3K★ | 极活跃（2026-05 仍频繁更新） |
| **Sourcebot** | 自托管代码搜索+AI问答 | Zoekt 引擎 + SCIP 代码导航 | Fair Source, 3.4K★ | 活跃（v4.17.2） |
| **Zoekt** | 底层代码搜索引擎 | 三元组索引 + ctags 符号 | Apache-2.0, 1.6K★ | 活跃（Sourcegraph 维护） |
| **SCIP** | 代码智能协议 | 语言无关的索引格式 | Apache-2.0, 634★ | 活跃 |
| **Aider repo-map** | AI 编程助手的代码地图 | Tree-sitter + PageRank | Apache-2.0（Aider 内置） | Aider 一部分 |
| **bloop** | 本地代码搜索+AI问答 | Tantivy + Qdrant + Tree-sitter | Apache-2.0, 9.5K★ | **已归档（2025-01 停更）** |

### 交叉判断

对于中小型单仓项目，**不需要重型基础设施（Sourcegraph 企业版），但需要让 AI 能快速理解项目结构和调用关系。**

## 五个方案详解

### 方案 A：Repomix — 一键打包给 AI（推荐首选）

**是什么**：把整个仓库打包成一个 AI 友好的文件（XML/Markdown/JSON），可以直接喂给 Claude/GPT/DeepSeek。

**适用条件**：
- 项目规模适中，整个打包后 token 可控
- `--compress` 模式用 Tree-sitter 提取函数签名，token 减少 ~70%
- 支持 MCP 协议，VS Code 里直接用

**怎么用**：

```bash
# 安装
npm install -g repomix

# 进入项目目录，一键打包
cd ./example-repo
repomix

# 压缩模式（只保留签名和结构，token 少 70%）
repomix --compress

# 只打包核心代码
repomix --include "**/*.py" --ignore "**/venv/**,**/node_modules/**"

# 输出 Markdown 格式（更易读）
repomix --style markdown --compress -o example-index.md
```

**作为 MCP 服务器使用**（让 AI Agent 随时查代码）：

```json
// VS Code settings.json 或 MCP 配置
{
  "mcpServers": {
    "repomix": {
      "command": "npx",
      "args": ["-y", "repomix", "--mcp"]
    }
  }
}
```

**优点**：零基础设施、一行命令、AI 友好、支持 MCP  
**缺点**：每次打包是全量快照，不是实时索引；大项目 token 可能超限  
**成本**：免费，0 运维

---

### 方案 B：Zoekt — 本地代码搜索引擎

**是什么**：Google 内部代码搜索工具的开源版本，基于三元组索引，搜索极快。

**为什么适合**：需要高频搜索多个本地仓库时（例如跨多个独立仓库检索）。

**怎么用**：

```bash
# 安装（需要 Go 环境）
go install github.com/sourcegraph/zoekt/cmd/zoekt-index@latest
go install github.com/sourcegraph/zoekt/cmd/zoekt@latest
go install github.com/sourcegraph/zoekt/cmd/zoekt-webserver@latest

# 索引本地仓库
zoekt-index -index ~/.zoekt ./example-repo

# 命令行搜索
zoekt "example_function" 
zoekt "WebSocket file:*.py"

# 启动 Web UI
zoekt-webserver -index ~/.zoekt/
# 访问 http://localhost:6070
```

**Docker 一键启动**：

```bash
# 先索引
docker run --rm -v "./example-repo:/src" -v "$PWD/zoekt-data:/data" \
  ghcr.io/sourcegraph/zoekt \
  zoekt-index -index /data/index /src

# 启动搜索服务
docker run --rm -p 6070:6070 -v "$PWD/zoekt-data/index:/data/index" \
  ghcr.io/sourcegraph/zoekt
```

**优点**：极快（毫秒级）、支持正则、支持符号搜索（配合 ctags）  
**缺点**：需要 Go 环境或 Docker、无 AI 问答能力、纯文本搜索无语义理解  
**成本**：免费，轻量运维

---

### 方案 C：Sourcebot — 自托管代码搜索 + AI 问答

**是什么**：在 Zoekt 之上封装了 Web UI、代码导航（Go to definition）、AI 问答能力的一站式方案。

**为什么适合**：想要类 Sourcegraph 体验但不想付费、且想用 AI 问答代码的场景。

**怎么用**：

```bash
# 1. 下载 docker-compose.yml
curl -o docker-compose.yml https://raw.githubusercontent.com/sourcebot-dev/sourcebot/main/docker-compose.yml

# 2. 创建配置文件（索引本地目录）
echo '{
  "$schema": "https://raw.githubusercontent.com/sourcebot-dev/sourcebot/main/schemas/v3/index.json",
  "connections": {
    "local-repos": {
      "type": "local",
      "path": "/repos"
    }
  }
}' > config.json

# 3. 挂载本地仓库目录并启动
docker compose up

# 4. 访问 http://localhost:3000
```

**功能**：
- 代码搜索（正则 + 布尔逻辑 + 语言过滤）
- IDE 级代码导航（跳转定义、查找引用）
- Ask Sourcebot（自然语言问答，带代码引用）
- 文件浏览器

**优点**：功能最全、有 AI 问答、IDE 级导航  
**缺点**：需要 Docker、需要配置 LLM API key（用于 AI 问答）、资源占用较大  
**成本**：免费（开源版），AI 问答需自己提供 LLM API

---

### 方案 D：Aider repo-map — AI 编程助手内置

**是什么**：Aider（AI 编程助手）内置的仓库地图功能，用 Tree-sitter 解析 AST + PageRank 排序，动态生成最相关的代码骨架。

**为什么适合**：如果你已经在用 Aider 做 AI 辅助编程，这是免费附带的。

**怎么用**：

```bash
# 安装 Aider
pip install aider-chat

# 进入项目目录
cd ./example-repo

# 启动 Aider（自动生成 repo-map）
aider

# repo-map 会自动包含在每次 LLM 调用中
# 可以用 --map-tokens 控制地图大小（默认 1K tokens）
aider --map-tokens 2048
```

**优点**：零额外配置、动态调整（只展示当前对话相关的代码）、PageRank 排序准确  
**缺点**：只在 Aider 内有效、不能独立使用、不是持续搜索服务  
**成本**：免费（Aider 开源），但 LLM API 调用费照常

---

### 方案 E：SCIP + Tree-sitter 自建索引（DIY 方案）

**是什么**：用 SCIP 协议生成精确的代码索引（定义、引用、实现），实现 IDE 级精度的跨文件导航。

**为什么**：如果你有非常定制化的需求（比如要集成到自己的 AI Agent 工具链中）。

**怎么用**：

```bash
# Python 索引器
pip install scip-python
# 生成 SCIP index
scip-python index . --output index.scip

# TypeScript 索引器
npm install -g @sourcegraph/scip-typescript
scip-typescript index --output index.scip

# 用 scip CLI 查看索引
go install github.com/scip-code/scip/cmd/scip@latest
scip print index.scip  # 查看索引内容
scip stats index.scip  # 统计信息
```

**优点**：最精确（编译器级别）、可集成到任何工具链  
**缺点**：需要为每种语言单独跑索引器、自己写查询逻辑、没有现成 UI  
**成本**：免费，但开发投入较高

## 选型决策树

```
你想解决什么问题？
│
├─ "让 AI 一次性理解整个项目" → Repomix（方案 A）
│   ├─ 项目 < 50K 行 → repomix --compress 直接打包
│   └─ 项目 > 50K 行 → repomix --include "核心目录" 选择性打包
│
├─ "日常高频搜代码（关键字/正则）" → Zoekt（方案 B）
│   ├─ 只有 1-2 个仓库 → 命令行 zoekt 就够
│   └─ 多个仓库 → zoekt-webserver Web UI
│
├─ "搜代码 + 跳转定义 + AI 问答 全都要" → Sourcebot（方案 C）
│   └─ 接受 Docker 运维成本 → docker compose up
│
├─ "AI 辅助写代码时自动理解上下文" → Aider repo-map（方案 D）
│
└─ "要集成到自己的 Agent/工具链" → SCIP 自建（方案 E）
```
