# Agent Loop 基线分析

## 结论
`naive_loop.py` 适用于教学场景，但不适合用于生产环境。`loop.py` 包含了完整的校验、授权和持久化机制，应作为生产环境的基线选择。

## 背景
在开发过程中，需要选择一个可靠的 Agent Loop 基线，以确保生产环境的稳定性和可靠性。`naive_loop.py` 和 `loop.py` 是两个候选方案，需要分析它们的控制权分布，以决定哪个更适合生产环境。

## 证据
1. **`naive_loop.py` 的问题**：
   - 缺乏校验和持久化机制。
   - 模型建议、工具执行、事实记录和停止判断之间没有可靠边界。
   - 一旦进程崩溃，整个 Loop 不知道之前执行到了哪里。

2. **`loop.py` 的优势**：
   - 包含完整的校验、授权和持久化流程。
   - 模型建议只是候选动作，Harness 负责校验、授权和执行。
   - 工具结果才是事实，Harness 持久化记录。
   - 停止权由 Harness 决定，确保任务目标完成。

## 方案取舍
- **`naive_loop.py`**：
  - 优点：简单易懂，适合教学。
  - 缺点：缺乏生产环境所需的机制，不可靠。

- **`loop.py`**：
  - 优点：包含完整的校验、授权和持久化机制，适合生产环境。
  - 缺点：代码量较大，复杂度较高。

## 建议路线
1. 将 `loop.py` 作为生产环境的基线。
2. 完成真实数据库与模型的联调，确保数据一致性。
3. 完成 Docker 镜像与迁移验证，确保部署过程的稳定性。
4. 进行服务器 soak 测试，验证生产环境的稳定性。
