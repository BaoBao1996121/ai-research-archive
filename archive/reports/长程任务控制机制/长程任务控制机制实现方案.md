# 长程任务控制机制实现方案

## 结论
长程任务控制机制通过 `AssignmentContract`、`LocalPlan`、`Progress`、`Nudge` 和 `CompletionGate` 五个模块，实现了对长程任务的全流程控制，防止目标被降低、发现无效循环、纠偏跑偏行为，并阻止无证据的提前提交。

## 背景
长程任务通常涉及多轮交互和复杂操作，容易出现以下问题：
- **目标漂移**：模型可能在执行过程中降低目标要求。
- **无效循环**：模型可能在没有实质性进展的情况下重复相同动作。
- **证据不足**：模型可能在没有完成必要步骤的情况下提前提交结果。
- **动态调整困难**：模型需要根据执行情况动态调整计划。

为了解决这些问题，设计了长程任务控制机制，通过模块化的方式实现对任务的全流程管理。

## 证据
### 1. 模块实现
#### `AssignmentContract`
- **功能**：定义任务目标、退出条件、证据要求、约束和预算。
- **实现**：通过 `frozen=True` 防止执行过程中被修改。
- **代码实现**：见 [contracts.py](E:/LLM/AI/Crazy/crazy_harness/core/agents/contracts.py:23)。

#### `LocalPlan`
- **功能**：由 Agent 自主制定和修订任务步骤。
- **实现**：通过 `PlanEvent` 和 `reduce_plan()` 管理计划的创建、修订和执行状态。
- **代码实现**：见 [planning.py](E:/LLM/AI/Crazy/crazy_harness/core/agents/planning.py:66)。

#### `Progress`
- **功能**：判断任务是否实质性进展。
- **实现**：通过检查新增证据或状态变化判断进展。
- **代码实现**：见 [completion.py](E:/LLM/AI/Crazy/crazy_harness/core/agents/completion.py:79)。

#### `Nudge`
- **功能**：在任务跑偏或卡顿时进行纠偏。
- **实现**：分为固定提醒和动态规则提醒，动态提醒基于缺失证据或未完成操作生成。
- **代码实现**：见 [loop.py](E:/LLM/AI/Crazy/crazy_harness/core/agents/loop.py:463)。

#### `CompletionGate`
- **功能**：机械检查任务完成条件是否满足。
- **实现**：检查输出格式、必要证据和未完成操作。
- **代码实现**：见 [completion.py](E:/LLM/AI/Crazy/crazy_harness/core/agents/completion.py:108)。

### 2. 实际运行链路
以模型申请 `stop` 为例：
```text
模型返回 stop
-> AgentAction 格式校验
-> _execute()
-> _completion_allows()
-> CompletionGate.evaluate()
-> 发现缺少 test.run
-> 写入 completion.gate.failed
-> 写入 agent.nudged
-> 本轮结束，但任务不结束
-> 下一轮把 Nudge 塞入 Context
-> 再次调用模型
```

## 方案取舍
### 1. `Nudge` 提醒方式
- **固定提醒**：由开发者提前配置，适用于常见问题。
- **动态规则提醒**：基于任务状态生成，更灵活但实现复杂度较高。
- **选择**：当前采用动态规则提醒，结合固定提醒作为补充。

### 2. `Progress` 检测方式
- **基于证据变化**：通过检查新增证据判断进展。
- **基于动作变化**：通过检查动作变化判断进展。
- **选择**：当前采用基于证据变化的方式，更准确但实现复杂度较高。

### 3. `LocalPlan` 动态调整
- **静态计划**：计划在任务开始时固定，无法动态调整。
- **动态计划**：计划可以根据任务执行情况动态调整。
- **选择**：当前实现动态计划，但尚未完全接入主循环。

## 建议路线
1. **完成模块集成**：将 `ProgressDetector` 和 `LocalPlan` 完全接入 `AgentLoop`。
2. **优化 `Nudge` 机制**：增加对长期固定提醒的支持，优化动态提醒生成规则。
3. **完善 `Progress` 检测**：探索基于动作变化的检测方式，提高检测准确性。
4. **扩展 `CompletionGate`**：增加对更多任务类型的支持，优化检查规则。
