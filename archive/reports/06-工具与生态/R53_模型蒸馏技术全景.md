## 1. TL;DR 速查卡

| 关键问题 | 30 秒答案 |
|---------|----------|
| **蒸馏到底是什么** | 用大模型（Teacher）输出的「软标签 / 中间表示 / 排序关系 / 完整生成序列」当训练信号，让小模型（Student）学到接近大模型的能力。体积压缩 2-50×，速度提升 2-500× |
| **三大流派一句话** | ① Response（学输出概率）② Feature（学中间层）③ Relation（学样本/层之间的关系矩阵） |
| **LLM 蒸馏与 BERT 时代有什么不同** | 三个根本变化：① **生成 vs 分类**——目标从 token-level KL 转向 sequence-level（SeqKD）② **forward KL → reverse KL**（MiniLLM 论文证明 reverse KL 对生成更稳，避免 mode-averaging 幻觉）③ **off-policy → on-policy**（让学生自己生成，老师打分）|
| **DeepSeek-R1-Distill 怎么做的** | 黑盒数据蒸馏：用 R1 (671B) 生成 800K 高质量 reasoning 数据 → SFT 蒸到 Llama/Qwen 1.5B/7B/14B/32B。**没有用 RL，纯 SFT 就达成 SOTA**——证明高质量 trace 比复杂训练算法更重要 |
| **苹果 2025 Distillation Scaling Laws 关键结论** | ① 当老师已存在 + 要蒸多个学生 → 蒸馏明显优于 SFT；② 只蒸一个学生 + 老师也要从头训 → 直接 SFT 更划算（蒸馏的总 compute 反而更高）|
| **蒸馏 vs 量化怎么选** | **先量化，不够再蒸**。量化几乎零训练成本（QLoRA-4bit 一行代码），蒸馏要数据 + GPU 时间。两者**正交可叠加**：蒸完再量化是工业标准做法 |
| **当前最强工具栈** | 经典 KD：`sentence-transformers` / `FlagEmbedding`；LLM 黑盒蒸：`TRL` + `LLaMA-Factory` + 高质量 trace 数据；LLM 白盒蒸：`microsoft/LMOps/minillm`；超轻量静态蒸：`model2vec`（30 秒，无数据）|
| **不该蒸的场景** | ① 训练数据 < 10K + 没标注预算 → 直接用现成小模型（Qwen2.5-3B、bge-reranker-base）② 老师本身就弱（业务 baseline < 0.85） → 先优化老师 ③ 单学生 + 老师从头训 → SFT 更划算（见 Scaling Law 结论）|

**生命周期定位**：成熟期（产业部署刚需）+ 上升期（LLM 蒸馏的范式仍在演化）。
- 经典 KD（BERT/CV）：**深度成熟期**，理论框架稳定，主要在工程优化
- LLM 蒸馏：**快速演化期**，每年都有新范式（reverse KL → on-policy → sequence-level → reasoning trace）

### 横轴 · 竞争格局：模型压缩四大门派

| 门派 | 代表方法 | 设计哲学 | 典型压缩比 | 训练成本 | 与蒸馏的关系 |
|------|---------|---------|-----------|---------|-------------|
| **蒸馏 KD** | DistilBERT、MiniLLM、DeepSeek-R1-Distill | 用 teacher 信号训 smaller 架构 | 2-50× | 高（需训练）| —— |
| **量化 Quantization** | GPTQ、AWQ、bitsandbytes、QLoRA | 浮点 → 低位整数（INT8/INT4） | 2-8× | 低（PTQ 无需训练）| ✅ 正交可叠加 |
| **剪枝 Pruning** | LLM-Pruner、SparseGPT、Wanda | 删除不重要权重/注意力头 | 1.5-3× | 中（需恢复训练）| ✅ 互补，剪枝+蒸馏经典组合 |
| **稀疏激活 / MoE** | Switch、Mixtral、DeepSeekMoE | 只激活部分专家 | 推理 FLOPs 4-8× | 设计阶段 | 互补，可在 MoE 上做蒸馏 |
| **架构替换** | Mamba、RWKV、Linear Attention | 换更高效的算子 | 不同模型 | 需重训 | 替代关系（不一定要蒸） |

### 设计哲学差异

- **量化** = 让每个权重「数字小一点」，结构不变
- **剪枝** = 让权重「数量少一点」，参数稀疏
- **蒸馏** = 让模型「换一个更小的脑子」，重新学
- 三者**正交可叠加**：「蒸馏出 6-layer → INT4 量化 → 部分剪枝」是 2025 工业标准 pipeline

### 交叉判断（独立结论）

- **蒸馏靠不靠谱**：靠谱。10 年沉淀 + 工业大规模应用（DistilBERT 月下载量 1100 万+，bge-reranker-v2-m3 月下载 814 万+），不是花哨 trick，是部署刚需
- **该不该选蒸馏**：取决于卡在哪——
  - 卡在**模型太慢** → 先量化 + Flash Attention（投入产出比最高）
  - 卡在**模型装不下** → 量化 + 蒸馏组合
  - 卡在**老师 API 太贵想本地化** → 黑盒蒸馏（DeepSeek-R1-Distill 路线）
  - 卡在**单一任务想要小而精的学生** → 白盒蒸馏（MiniLLM 路线）
  - 卡在**边缘部署/嵌入式/无 GPU** → 静态蒸馏（model2vec）
- **本工作区视角**：与 [模型训练与微调技术全景调研](R52_%E6%A8%A1%E5%9E%8B%E8%AE%AD%E7%BB%83%E4%B8%8E%E5%BE%AE%E8%B0%83%E6%8A%80%E6%9C%AF%E5%85%A8%E6%99%AF.md) 形成"训完大模型如何瘦身部署"的下半场

## 3. 📚 第一性原理：为什么蒸馏可行

> Hinton 的核心 insight：**大模型输出的概率分布本身就携带「暗知识（Dark Knowledge）」**——不仅告诉你答案是「猫」，还告诉你「这张图 90% 像猫、8% 像虎、2% 像狗」。这种**类间相对关系**比 one-hot 标签信息量大得多。

### 三个关键概念

**① Soft Target（软标签）**

```
硬标签：[0, 1, 0, 0]              （独热编码，信息量 = log2(4) = 2 bit）
软标签：[0.05, 0.85, 0.08, 0.02]  （teacher 输出的概率分布，信息量 ≈ 0.84 bit 的熵）
```

软标签包含的信息量更大——它告诉学生"猫和虎之间的相似度比猫和狗高"，这种相似性是**模型隐式学到的世界知识**。

**② Temperature Scaling（温度缩放）**

$$p_i = \frac{\exp(z_i / T)}{\sum_j \exp(z_j / T)}$$

- T=1：标准 softmax
- T=10：分布更平缓，类间差异被放大暴露（更多暗知识）
- T→∞：均匀分布

训练时常用 T=2~10，**推理时 T=1**。

**③ KD Loss = 蒸馏损失 + 真实标签损失**

$$\mathcal{L} = \alpha \cdot T^2 \cdot \mathrm{KL}(p^T_{\text{teacher}} \,\|\, p^T_{\text{student}}) + (1 - \alpha) \cdot \mathrm{CE}(y_{\text{true}}, p_{\text{student}})$$

- 第一项：学生的软分布要逼近老师的软分布（模仿）
- 第二项：学生也要学对真实标签（兜底）
- α 通常取 0.5~0.9，T² 是因为梯度被 T² 缩放需要补偿

### 停下来想一想 🤔

> **Q1：为什么一个 6 层 BERT 直接训练效果不如「先训 12 层 → 蒸到 6 层」？**
>
> A：12 层 BERT 在大规模预训练中学到了**复杂的特征空间和决策边界**，这种"地形"对 6 层网络来说是"指路明灯"。从零训练 6 层 = 蒙着眼摸索；蒸馏 6 层 = 跟着导游走。这就是 Bengio 说的"老师把 loss landscape 变得更平滑"。
>
> **Q2：如果老师本身有错误偏见，蒸馏会不会把偏见放大？**
>
> A：**会，且更严重**。这是蒸馏的根本风险——学生不仅继承老师的能力，也继承老师的盲区和偏见。所以蒸馏前必须评估：老师在你的目标领域上 baseline 是否够高（一般 ≥ 0.85）。Apple 的 Scaling Law 论文也指出，老师能力封顶 = 学生能力封顶。

## 4. 📚 蒸馏的三大经典流派

KD 按"学生模仿老师的什么"分三大类：

```
                            ┌─ Response-based KD（响应蒸馏）
                            │  学最终输出概率
                            │  代表：Hinton's KD、DistilBERT
                            │  特点：黑盒友好，简单，信息量有限
                            │
   Knowledge Distillation ──┼─ Feature-based KD（特征蒸馏）
                            │  学中间层的隐藏状态、注意力图
                            │  代表：FitNet、TinyBERT、PKD
                            │  特点：信息量大，需对齐维度，必须白盒
                            │
                            └─ Relation-based KD（关系蒸馏）
                               学「样本之间的关系」或「层之间的关系」
                               代表：MiniLM、RKD、CRD
                               特点：解耦学生/老师架构尺寸约束
```

### 4.1 Response-based（响应蒸馏）

**做什么**：学生只看老师的最终输出（logits 或概率分布）

**优点**：
- **黑盒友好**——只要能拿到 teacher 输出就行（连 GPT-4 这种 API-only 模型都能蒸）
- 实现最简单，loss 函数 5 行写完
- 适合所有任务（分类、生成、回归）

**缺点**：
- 信息量有限——老师内部"怎么想的"完全丢失
- 学生架构差异大时效果打折（小学生 capacity 不够吸收完整分布）

**典型实现**：DistilBERT（论文 [arXiv:1910.01108](https://arxiv.org/abs/1910.01108)）
- 6-layer Student vs 12-layer BERT-base Teacher
- Triple Loss：MLM + KD + Cosine Embedding Loss
- 结果：97% GLUE 性能，60% 推理加速，40% 体积压缩

### 4.2 Feature-based（特征蒸馏）

**做什么**：学生不仅学输出，还要学**中间隐藏层**和**注意力图**

**优点**：
- 信息量大——老师的"思考过程"被保留
- 在小学生模型上效果显著超过 Response-only

**缺点**：
- 需要 Student 和 Teacher 中间层维度对齐（或加 projection layer）
- 必须能拿到 teacher 内部状态——**白盒蒸馏**
- 训练显存吃紧（同时跑两个模型）

**典型实现**：TinyBERT（4-layer + hidden=312，达到 BERT-base 96% 性能，9.4× 加速）

### 4.3 Relation-based（关系蒸馏）

**做什么**：学生学的不是"具体的隐藏状态值"，而是"样本之间的关系"或"注意力头之间的关系"

**MiniLM 的关键创新**：蒸馏 **Self-Attention Q-Q / K-K / V-V 的关系矩阵**而不是 Q-K-V 本身。这样 Student 可以有完全不同的 hidden size，依然能学到老师的"注意力模式"。

**为什么这种范式重要**：它解耦了"学生架构"和"老师架构"的尺寸约束。MiniLM-L6 可以从 12-layer / 24-layer 任何老师蒸馏出来。

**典型实现**：MiniLM v1/v2、RKD（Relational KD）、bge-m3 的多向量 self-distillation

## 5. 📚 LLM 时代的范式迁移（重点新增）

> 经典 KD 是为**判别式模型**（分类/回归）设计的，直接套到**生成式 LLM** 上效果差。2023-2025 是 LLM 蒸馏方法论快速重构的三年——以下五个范式迁移是核心。

### 5.1 范式迁移 A：Token-level → Sequence-level（SeqKD）

**问题**：传统 KD 在每个 token 位置上算 KL 散度。但生成式任务的语义在**整个序列**层面，单 token 对齐意义不大。

**解决方案 SeqKD（Kim & Rush, 2016）**：
1. 让 teacher 用 beam search 生成完整的高质量序列
2. 把 (input → teacher_output) 作为新数据集
3. 学生在这个数据集上做标准 SFT

**这就是 Alpaca / Vicuna / DeepSeek-R1-Distill 的本质**——用 SeqKD 框架理解，它们都不是"复杂的蒸馏算法"，而是"高质量数据 SFT"。

### 5.2 范式迁移 B：Forward KL → Reverse KL（MiniLLM 论文）

**问题**：forward KL $\mathrm{KL}(p_T \| p_S)$ 会让学生**高估老师的低概率区域**——也就是说，学生会模仿老师"偶尔说错的话"，导致幻觉放大。

**MiniLLM 的发现**（[arXiv:2306.08543](https://arxiv.org/abs/2306.08543), ICLR 2024）：

```
Forward KL：KL(p_teacher || p_student)
   ↓
学生分布要"覆盖"老师所有 mode → mode-averaging → 容易生成模糊/平庸的文本

Reverse KL：KL(p_student || p_teacher)  ✨ MiniLLM 关键
   ↓
学生分布要"集中在"老师的高概率区域 → mode-seeking → 生成更精准的文本
```

**直觉类比**：
- Forward KL = 让学生"什么都会一点"（什么都答得出，但都不精）
- Reverse KL = 让学生"专精老师最确信的事"（不知道就不说，已知就说准）

**实测效果**：MiniLLM 在 GPT-2 / OPT / LLaMA 上证明 reverse KL 训练的学生在 instruction-following、长文生成、calibration 上全面优于 forward KL。

### 5.3 范式迁移 C：Off-policy → On-policy

**问题**：经典蒸馏是 off-policy——学生只在「老师已经生成好的样本」上学习。这导致**exposure bias**：训练时见到的是老师的高质量输出，推理时学生自己生成的输出分布完全不同（distributional shift）。

**On-policy 蒸馏**（MiniLLM、GKD 等）：
1. 让**学生先自己生成**一批样本
2. **老师对学生的输出打分**（提供 KL 梯度）
3. 学生在自己的输出上学习改进

**GKD（Generalized KD）的关键贡献**：把 on-policy + reverse KL + 混合分布采样（学生分布 + 老师分布）统一到一个框架。

### 5.4 范式迁移 D：纯输出蒸馏 → Reasoning Trace 蒸馏

**问题**：让学生只学最终答案，浪费了老师的「思维链」（CoT）信息。

**Distillation Step-by-Step（Google, 2023）**：让 teacher 同时生成「答案 + reasoning rationale」，学生学两件事：
1. 主任务：根据 input 生成 reasoning + answer
2. 辅任务：根据 input + rationale 预测 answer

**DeepSeek-R1-Distill 是这条路线的工业级实现**：
- Teacher = DeepSeek-R1（671B，带 RL 训练出的 long reasoning）
- 数据 = 800K 条「question → reasoning → answer」三元组
- 学生 = Llama-3.1-8B / Qwen2.5-32B 等
- **关键发现**：纯 SFT 蒸馏 reasoning trace，已经能让 7B 学生在 AIME 数学竞赛上超过 GPT-4o

> **这是 2025 年最重要的发现之一**：「reasoning 能力可以通过数据蒸馏」打破了"小模型不能 reason"的固有认知。

### 5.5 范式迁移 E：黑盒 vs 白盒蒸馏的 LLM 实战分野

```
黑盒蒸馏（Black-box KD）—— 现实主流
─────────────────────────────────────────
  Teacher (GPT-4 / Claude / DeepSeek-R1)
            │
            ▼ 生成大量 (input → output) 数据
   Pseudo-labeled Dataset
            │
            ▼ SFT 训练
       Student (Llama / Qwen / Mistral)
─────────────────────────────────────────
  ✅ 优点：teacher 完全黑盒可用
  ❌ 缺点：信息利用率低（只用最终输出）
  📌 代表：Alpaca、Vicuna、DeepSeek-R1-Distill 系列
  📌 工程难度：⭐⭐（主要是数据工程）


白盒蒸馏（White-box KD）—— 学术前沿
─────────────────────────────────────────
  Teacher (开源大模型，可访问 logits/hidden states)
            │
            ▼ 同时算 reverse KL / 特征对齐 / 关系对齐
       Student (小模型)
─────────────────────────────────────────
  ✅ 优点：信息利用率高，效果上限更高
  ❌ 缺点：teacher 必须开源 + 显存吃紧（同时跑两个模型）
  📌 代表：MiniLLM、Distillm、GKD
  📌 工程难度：⭐⭐⭐⭐（涉及强化学习和分布对齐）
```

**实战经验**：
- 你不是研究机构 → 用黑盒（DeepSeek-R1-Distill 路线），数据工程是关键
- 你有 8×A100 + 想发论文 → 用白盒（MiniLLM 路线）
- 你的老师是专有 API（GPT-4、Gemini） → 只能用黑盒

### 5.6 范式迁移 F：Distillation Scaling Laws（2025 苹果论文）

**苹果 ICML 2025 论文** [arXiv:2502.08606](https://arxiv.org/abs/2502.08606) 第一次系统刻画了蒸馏的 compute-optimal 边界：

#### 关键结论

| 场景 | 推荐方案 | 理由 |
|------|---------|------|
| **老师已经存在 + 要蒸多个学生**（如 DistilBERT 服务千万下载量）| ✅ **强烈推荐蒸馏** | 老师 compute 已沉没成本，蒸馏 compute 远低于 SFT |
| **老师已经存在 + 只蒸一个学生** | ✅ 推荐蒸馏 | 仍优于 SFT，但优势缩小 |
| **老师需要从头训 + 只蒸一个学生** | ❌ **不要蒸馏** | 总 compute（老师训练 + 蒸馏）比直接 SFT 大 |
| **老师需要从头训 + 蒸多个学生** | 临界 | 视学生数量决定 |

#### 一个反直觉但重要的结论

> **过去的"蒸馏总是比 SFT 好"是错觉，因为大家忽略了 teacher 的训练成本。真正的 compute-optimal 决策必须把 teacher 训练算进去。**

实践含义：
- 公司想把 GPT-4 (API) 的能力蒸到自家小模型 → ✅ 蒸馏（老师 sunk cost）
- 公司想训一个 30B 老师然后蒸到 7B → ❌ 直接训 7B 更划算
- 开源社区放出 70B teacher → ✅ 全社区蒸学生（每个学生都是 marginal）

### 5.7 LLM 蒸馏的损失函数全景

```
经典 KD：           α · KL(p_T || p_S) + (1-α) · CE(y_true, p_S)
SeqKD：            CE(y_teacher_seq, p_S)         ← 退化为 SFT
Reverse KL (MiniLLM):  KL(p_S || p_T)
Generalized KD:    α · D_f(p_T, p_S) + λ · D_f(p_S || p_T_on_student_samples)
Distillm:          通过 skewed KL 平衡 forward/reverse
ULD (Universal LD): 不同 tokenizer 之间的蒸馏（Wasserstein 距离）
```

> 不需要全部记住，关键是：**生成式任务首选 SeqKD（数据蒸馏） 或 Reverse KL（白盒）**，分类/回归任务用经典 KD。

## 6. 📚 与「邻居技术」的边界

| 技术 | 解决什么 | 何时用 | 与蒸馏的关系 |
|------|---------|--------|-------------|
| **量化 (PTQ/QAT)** | 模型太大装不下 / 推理太慢 | 90% 场景的第一选择 | 正交可叠加（蒸完再量化）|
| **剪枝 (Wanda/SparseGPT)** | 模型有冗余参数 | 已知结构稀疏性时 | 互补（剪枝 + 蒸馏 = 经典组合）|
| **PEFT (LoRA/QLoRA)** | 微调成本太高 | 适配新任务时 | 不同维度——LoRA 是少改参数，蒸馏是换小模型 |
| **MoE (Mixtral, DeepSeekMoE)** | 想保持容量但减少推理成本 | 设计新模型时 | 设计阶段决策，可在 MoE 上做蒸馏 |
| **Speculative Decoding** | 推理加速 | 推理 serving 阶段 | **关联但不同**：speculative decoding 用一个小 draft 模型加速大模型推理，draft 模型本身可以是蒸馏出来的 |
| **直接换小模型** | 真的不需要那么大能力 | 任务简单 + 评估证明小模型够用 | **优先尝试这个**——别为了蒸而蒸 |

> **反直觉但重要**：80% 的"我想做蒸馏"需求，**用现成小模型 + INT8 量化 + 缓存**就解决了。先验证「现成小模型够不够」再考虑蒸馏。

## 7. 🎯 五大典型应用场景

> 蒸馏不是单一技术，而是一族解决不同问题的方法。下表把蒸馏在 LLM 时代的主要应用场景一字排开：

| 场景 | 典型代表 | 适用范式 | 难度 | 现状 |
|------|---------|---------|------|------|
| **A. LLM 通用能力蒸馏** | Alpaca/Vicuna/DeepSeek-R1-Distill | SeqKD（黑盒）| ⭐⭐ | 主流，已工业化 |
| **B. LLM 专项能力蒸馏（reasoning/code/agent）** | DeepSeek-R1-Distill、s1、SimpleScaling | Reasoning Trace + SeqKD | ⭐⭐⭐ | 2025 最火方向 |
| **C. Embedding 蒸馏** | bge-m3 self-distillation、potion-multilingual | Self-KD + Triple Loss | ⭐⭐ | 成熟 |
| **D. Rerank/Cross-Encoder 蒸馏** | MiniLM-L6 reranker、bge-reranker-v2.5-lightweight | MarginMSE + Layer Reduction | ⭐⭐ | 成熟 |
| **E. 视觉/多模态蒸馏** | DistilCLIP、SmolVLM | Feature + Response | ⭐⭐⭐ | 上升期 |

### 7.A LLM 通用能力蒸馏

**典型场景**：把 GPT-4 / Claude / DeepSeek-V3 的对话能力蒸到 Llama-3-8B / Qwen2.5-7B

**方法**：
1. 收集多样化的 prompt（10K-1M 条）
2. 让 teacher 生成回复
3. 学生在 (prompt, teacher_response) 上 SFT
4. 可选：加 RLHF / DPO 进一步对齐

**关键点**：
- 数据多样性 > 数据量。10K 高质量比 1M 同质化效果好
- 学生不要太小——< 1B 学不到复杂指令遵循
- Vicuna-7B（用 70K ShareGPT 数据蒸 GPT-3.5）证明了这条路线的可行性

### 7.B LLM 专项能力蒸馏（2025 最热）

**典型场景**：让小模型学会 reasoning / code / agent

#### B.1 Reasoning 蒸馏（DeepSeek-R1-Distill 路线）

```
DeepSeek-R1 (671B)
     │
     ▼ 生成 800K 条「question → <think>...</think> → answer」
     │
     ▼ SFT
Llama-3.1-8B / Qwen2.5-7B / Qwen2.5-32B
     ↓
在 AIME / MATH / GPQA 上达到接近 GPT-4o 水平
```

**关键工程问题**：
- 哪些数据进入蒸馏集？→ DeepSeek 论文披露：拒绝采样（rejection sampling）只保留 R1 答对的题
- reasoning 长度需要截断吗？→ 不截，让学生学会"长思考"
- 需要 RL 阶段吗？→ R1 论文消融实验显示 SFT 阶段已经达成大部分提升，RL 是锦上添花

#### B.2 Agent 能力蒸馏（新兴方向）

把大模型的 tool use / planning / multi-step reasoning 蒸到小模型，让 Agent 部署可负担。
- 代表项目：xLAM、Hermes 系列函数调用模型、Llama Stack agent distillation
- 数据：(user_query → tool_call_sequence → final_answer) trace

### 7.C Embedding 蒸馏

**典型场景**：把 bge-m3 (568M) 蒸成 potion-multilingual-128M（4× 压缩，可在 CPU 跑）

**方法**：
- **Self-KD**（bge-m3）：让 dense / sparse / multi-vector 三种输出互相蒸馏
- **静态蒸馏**（model2vec）：把整个 embedding 模型压成查表 + mean pooling

**评估指标**：MTEB / MMTEB / BEIR 跨领域 nDCG

### 7.D Rerank / Cross-Encoder 蒸馏（用户提到的场景）

**为什么常被蒸**：Cross-Encoder 必须 query × doc 逐对推理（O(N)），bge-reranker-large 在 CPU 上 100 docs 要 2-3 秒；蒸馏后可降到 100ms 以内。

**三条主流路径**：

```
                              用户场景：Rerank 太慢
                                       │
                ┌──────────────────────┼──────────────────────┐
                │                      │                      │
        路径 1：              路径 2：              路径 3：
   蒸到小 Cross-Encoder   蒸到 Bi-Encoder      静态蒸馏 / 极简
        │                      │                      │
   架构：MiniLM-6L         架构：双塔 + Distil      架构：Token 平均嵌入
   保持精度，快 3-5×       极致快 100×            快 500×，精度大降
   工具：sentence-trans    工具：sentence-trans    工具：model2vec
   📌 主流首选            📌 ColBERTv2 思路       📌 边缘部署 / CPU
```

**官方参考**（[sbert.net](https://www.sbert.net/examples/sentence_transformer/training/distillation/README.html)）：
| Teacher 12 层 → Student | 性能保留 | 速度提升 |
|------------------------|---------|----------|
| 8 层 | +0.1% | 1.4× |
| 6 层 | -0.2% | 1.7× |
| 4 层 | -0.6% | 2.3× |
| 2 层 | -2.5% | 3.3× |

**关键技巧**：**Layer Reduction 而不是 Train From Scratch**——直接保留 teacher 的某些层（如第 0, 2, 4, 6, 8, 10 层）作为 student 初始化，比从零训 6 层效果好得多。

**Loss 选择**：
- `MarginMSELoss`（最常用）：让学生学到的「正样本-负样本 margin」逼近老师
- `MSELoss(student_score, teacher_score)`：直接 MSE 拟合分数
- `ListMLE` / `RankNet`：保持 ranking order

**为什么用 Margin 而不是绝对分数**：Rerank 的本质是「排序」，不是「打分」。学生只要保留**相对顺序**就够。

### 7.E 视觉 / 多模态蒸馏

- **DistilCLIP**：把 CLIP-L/14 蒸成 CLIP-B/32，retrieval 性能保留 95%
- **SmolVLM**（HuggingFace 2024）：3B 多模态模型，VQA 接近 GPT-4V
- **MobileSAM**：把 Segment Anything Model 蒸成移动端可跑版本

主要方法：Feature-based KD（视觉特征对齐）+ Response-based KD（输出层）。

### Hello World #2：经典 BERT 蒸馏（DistilBERT 思想最小复现）

**目标**：把 BERT-base 蒸到 6-layer，理解 KD Loss 的具体写法。

```python
# distill_bert_classification.py
import torch
import torch.nn as nn
import torch.nn.functional as F
from transformers import AutoModelForSequenceClassification, AutoTokenizer
from datasets import load_dataset

# === 加载 Teacher 和 Student ===
TEACHER = "textattack/bert-base-uncased-SST-2"
STUDENT_BASE = "distilbert-base-uncased"

teacher = AutoModelForSequenceClassification.from_pretrained(TEACHER).eval()
student = AutoModelForSequenceClassification.from_pretrained(STUDENT_BASE, num_labels=2)
tokenizer = AutoTokenizer.from_pretrained(TEACHER)

# 冻结 teacher 参数（关键！）
for p in teacher.parameters():
    p.requires_grad = False

# === KD Loss 实现 ===
def kd_loss(student_logits, teacher_logits, labels, T=4.0, alpha=0.7):
    """经典 Hinton KD Loss"""
    soft_targets = F.softmax(teacher_logits / T, dim=-1)
    soft_prob = F.log_softmax(student_logits / T, dim=-1)
    distill_loss = F.kl_div(soft_prob, soft_targets, reduction="batchmean") * (T ** 2)
    ce_loss = F.cross_entropy(student_logits, labels)
    return alpha * distill_loss + (1 - alpha) * ce_loss

# === 训练循环（演示，省略 dataloader 细节）===
ds = load_dataset("sst2", split="train[:1000]")
optimizer = torch.optim.AdamW(student.parameters(), lr=5e-5)

for batch in ds.batch(16):
    inputs = tokenizer(batch["sentence"], padding=True, truncation=True, return_tensors="pt")
    labels = torch.tensor(batch["label"])
    with torch.no_grad():
        teacher_logits = teacher(**inputs).logits
    student_logits = student(**inputs).logits
    loss = kd_loss(student_logits, teacher_logits, labels)
    loss.backward()
    optimizer.step()
    optimizer.zero_grad()
    print(f"loss={loss.item():.4f}")
# Expected: loss 从 ~1.5 收敛到 ~0.3-0.5
```

**得到什么**：掌握 KD Loss 的实际代码——这是所有蒸馏方法的根基。

### Hello World #3：Cross-Encoder Rerank 蒸馏

**目标**：把 12-layer cross-encoder 蒸成 6-layer，保持 95%+ 性能。

```python
# distill_cross_encoder.py
from sentence_transformers.cross_encoder import CrossEncoder
from sentence_transformers import losses, InputExample
from torch.utils.data import DataLoader
from transformers import AutoModelForSequenceClassification, AutoTokenizer
import torch.nn as nn

# === Step 1: 加载 Teacher ===
teacher = CrossEncoder("BAAI/bge-reranker-base", max_length=512)

# === Step 2: 准备数据（替换为你的业务 triplets）===
queries_pos_neg = [
    ("what is panda", "Giant panda is a bear native to China.", "Hi there"),
    ("北京美食", "北京烤鸭、炸酱面、卤煮", "上海小笼包"),
    # ... 至少 10K 条
]

train_examples = []
for q, pos, neg in queries_pos_neg:
    pos_score = teacher.predict([(q, pos)])[0]
    neg_score = teacher.predict([(q, neg)])[0]
    # MarginMSE 用 (pos_score - neg_score) 当目标
    train_examples.append(InputExample(
        texts=[q, pos, neg],
        label=float(pos_score - neg_score)
    ))

# === Step 3: 初始化 Student（layer reduction：保留 teacher 的偶数层）===
teacher_hf = AutoModelForSequenceClassification.from_pretrained("BAAI/bge-reranker-base")
keep_layers = [0, 2, 4, 6, 8, 10]
teacher_hf.bert.encoder.layer = nn.ModuleList(
    [teacher_hf.bert.encoder.layer[i] for i in keep_layers]
)
teacher_hf.config.num_hidden_layers = 6
teacher_hf.save_pretrained("./student_init")
AutoTokenizer.from_pretrained("BAAI/bge-reranker-base").save_pretrained("./student_init")

# === Step 4: 训练 Student ===
student = CrossEncoder("./student_init", num_labels=1)
train_loss = losses.MarginMSELoss(student.model)
train_dataloader = DataLoader(train_examples, shuffle=True, batch_size=32)

student.fit(
    train_dataloader=train_dataloader,
    epochs=3,
    warmup_steps=1000,
    output_path="./bge-reranker-distilled-6L",
)

# === Step 5: 验证 ===
test_pairs = [("what is panda", "The giant panda is a bear native to China"),
              ("what is panda", "Hi there")]
print("Teacher:", teacher.predict(test_pairs))
print("Student:", student.predict(test_pairs))
# Expected: 学生分数与老师 cosine 相似度 > 0.95
```

**得到什么**：6-layer reranker，体积约 110MB，速度比 base 快 ~2×，比 large 快 ~5×。

### Hello World #4：LLM 黑盒蒸馏（DeepSeek-R1-Distill 路线）

**目标**：用 DeepSeek-R1 当老师，蒸馏出小模型的推理能力。**这是 2025 年最重要的工程范式。**

```python
# distill_llm_blackbox.py
"""
完整流程分两阶段：
① 用 R1 生成蒸馏数据（API 调用）
② 用 LLaMA-Factory / TRL SFT 学生模型
"""

# === 阶段 ① 数据生成 ===
from openai import OpenAI
import json

client = OpenAI(
    api_key="sk-xxx",
    base_url="https://api.deepseek.com",
)

# 数学/代码 reasoning prompt 池（实际项目应有 10K+ 条）
prompts = [
    "求 x: 2x + 5 = 17",
    "实现 Python 二分查找，并解释思路",
    "证明√2 是无理数",
    # ...
]

with open("distill_data.jsonl", "w", encoding="utf-8") as f:
    for prompt in prompts:
        resp = client.chat.completions.create(
            model="deepseek-reasoner",  # R1
            messages=[{"role": "user", "content": prompt}],
        )
        msg = resp.choices[0].message
        # R1 特色：reasoning_content + content 双字段
        f.write(json.dumps({
            "instruction": prompt,
            "input": "",
```

### Hello World #5：LLM 白盒蒸馏（MiniLLM 简化版）

**目标**：用 reverse KL 把 GPT-2-medium (355M) 蒸到 GPT-2-small (125M)。

```python
# distill_llm_whitebox_minillm_lite.py
"""
MiniLLM 完整实现涉及强化学习，这里给出简化版只演示 reverse KL 思想。
完整版见 microsoft/LMOps/minillm GitHub 仓库。
"""
import torch
import torch.nn.functional as F
from transformers import GPT2LMHeadModel, GPT2Tokenizer

teacher = GPT2LMHeadModel.from_pretrained("gpt2-medium").eval()
student = GPT2LMHeadModel.from_pretrained("gpt2")
tokenizer = GPT2Tokenizer.from_pretrained("gpt2")
tokenizer.pad_token = tokenizer.eos_token

for p in teacher.parameters():
    p.requires_grad = False

def reverse_kl_loss(student_logits, teacher_logits, mask=None):
    """
    Reverse KL: KL(p_student || p_teacher)
    与 forward KL 的关键区别：
      - forward KL: target 是 teacher，会让 student 覆盖 teacher 所有 mode（mode-averaging）
      - reverse KL: target 是 student，让 student 集中在 teacher 高概率区（mode-seeking）
    """
    student_log_prob = F.log_softmax(student_logits, dim=-1)
    teacher_log_prob = F.log_softmax(teacher_logits, dim=-1)
    student_prob = student_log_prob.exp()
    # KL(p_S || p_T) = Σ p_S * (log p_S - log p_T)
    kl = (student_prob * (student_log_prob - teacher_log_prob)).sum(dim=-1)
    if mask is not None:
        kl = kl * mask
    return kl.mean()

prompts = ["The future of AI is", "Once upon a time"]
inputs = tokenizer(prompts, return_tensors="pt", padding=True)
optimizer = torch.optim.AdamW(student.parameters(), lr=1e-5)

for step in range(100):
    with torch.no_grad():
        teacher_logits = teacher(**inputs).logits
    student_logits = student(**inputs).logits
    loss = reverse_kl_loss(student_logits, teacher_logits, mask=inputs["attention_mask"])
    loss.backward()
    optimizer.step()
    optimizer.zero_grad()
    if step % 10 == 0:
        print(f"step={step}, reverse_KL={loss.item():.4f}")

# Expected: loss 从 ~3-5 缓慢下降到 ~0.5-1
# 完整 MiniLLM 还需 on-policy 采样 + PPO 优化，参见原仓库
```

**关键学习点**：
- 看到 reverse KL 与 forward KL 的代码差异（仅一个 `(student * ...)` vs `(teacher * ...)` 的差别）
- 理解 mode-seeking 行为如何减少幻觉

## 9. 🕳️ 避坑指南（15 条）

| # | 坑 | 原因 | 解法 |
|---|----|------|------|
| 1 | **Student 从零训效果远不如 Teacher 截层** | 6-layer 从随机初始化要重新学语言基础 | 始终用 Layer Reduction 或加载 DistilBERT/MiniLM 作为 Student 初始化 |
| 2 | **训练阶段忘记冻结 Teacher** | Teacher 参数被一起更新 | `for p in teacher.parameters(): p.requires_grad = False` |
| 3 | **Temperature 设错** | T=1 软标签退化为硬标签；T 太大梯度消失 | KD 阶段 T=2~10，配合 T² 缩放 loss；推理 T=1 |
| 4 | **MarginMSE Loss 训练不收敛** | 数据中 pos/neg margin 分布太窄 | 换更难的负样本（hard negatives，BM25 召回的近似项）|
| 5 | **Cross-Encoder 蒸到 Bi-Encoder 性能崩盘** | 双塔架构表达力上限低于交叉编码 | 接受 5-10% nDCG 下降，或改用 ColBERT 延迟交互架构 |
| 6 | **LLM 蒸馏只用 forward KL → 学生爱编瞎话** | mode-averaging 让学生覆盖老师低概率区 | 改用 reverse KL（MiniLLM）或 SeqKD（数据蒸馏）|
| 7 | **黑盒蒸馏数据漏标 reasoning** | 只存最终答案丢失思维链 | 抓取 `reasoning_content` + `content` 两段，用 `<think>` 标签封装 |
| 8 | **R1 蒸馏数据未做拒绝采样** | 老师答错的题也进训练集 | 必须先用 verifier 过滤（数学题对答案、代码题跑测试）|
| 9 | **量化后蒸馏分数失真** | INT8 量化后 logits 分辨率降低 | 蒸馏前评估"老师量化后分数是否仍可用"，必要时蒸完再量化 |
| 10 | **训练数据用了 Teacher 没见过的领域** | Teacher 在该领域本身就弱 | 先评估 Teacher 在你业务的 baseline，确认 ≥ 0.85 再蒸 |
| 11 | **model2vec 静态蒸馏期望太高** | 静态模型无法处理上下文相关语义 | 只用于召回粗筛，精排仍需 cross-encoder |
| 12 | **Reranker 输出未归一化直接用** | bge-reranker 默认输出 logits（无界） | `normalize=True` 走 sigmoid，或自行 softmax |
| 13 | **忽略 Tokenizer 不一致** | Teacher tokenizer ≠ Student tokenizer 直接蒸 | 必须用同 tokenizer，或用 Universal Logit Distillation (ULD) |
| 14 | **评估只看 in-domain，部署后效果暴跌** | KD 容易过拟合 teacher 偏差 | 必须用 BEIR / 跨领域测试集 + 业务真实流量 A/B |
| 15 | **不做 Distillation Scaling Law 检查** | 训了一个老师只蒸一个学生，总成本超 SFT | 决策前做：① teacher sunk cost？② 蒸几个学生？两题不通过就 SFT |

## 12. 结论与最佳实践

### 五条核心原则（适用所有蒸馏场景）

1. **先评估能不能不蒸**——80% 的"想蒸"需求可以用「现成小模型 + 量化 + 缓存」解决
2. **Layer Reduction > Train From Scratch**——直接从老师截层做 student 初始化，永远比从零训快、稳、好
3. **生成任务用 Reverse KL 或 SeqKD，分类任务用经典 Forward KL**——选错 loss 是 LLM 蒸馏失败的头号原因
4. **数据质量 > 数据量 > 算法复杂度**——DeepSeek-R1-Distill 用纯 SFT 就 SOTA，证明这一点
5. **决策前做 Scaling Law 检查**——单学生 + 老师从头训 = SFT 更划算，不要为蒸而蒸

### 按场景的最佳实践

#### LLM 通用/专项能力蒸馏（A/B 类）
1. 优先黑盒（除非你有 8×A100 + 时间）
2. 数据多样性 > 数量。10K 多样化 > 1M 同质化
3. 拒绝采样过滤（保留 teacher 答对的）
4. 学生不要太小（< 1B 学不到复杂指令）
5. SFT 已够，RL 是锦上添花

#### Embedding/Rerank 蒸馏（C/D 类）
1. 数据来源：80% MS MARCO + 20% 业务真实日志
2. Hard Negatives 必备：BM25 召回的近似项 > 随机负样本 2-3×
3. 训练目标：MarginMSE 学 ranking + InfoNCE 增强对比
4. 评估含 BEIR 跨领域：仅看自测试集会严重高估
5. 部署用 TEI（Text Embeddings Inference）：比 raw transformers 快 3-5×
