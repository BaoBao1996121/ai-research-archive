# Crazy 项目设计规范与实现路线

## 结论
Crazy 项目是一个轻量级、事件驱动的 A2A（Agent-to-Agent）项目，旨在通过手搓 agent 循环和工具调用机制，实现一个可运行、可回放、可讲解的 agent 团队协作示例。项目设计的核心机制包括事件驱动、工具网关、钩子系统、上下文管理、记忆机制和自进化能力。

## 背景
Crazy 项目的起源是希望不依赖现有 agent 框架，通过手动实现 agent 循环和编排，探索主流 A2A 和 agent 框架的核心机制。项目目标是打造一个能够展示事件驱动、工具调用、agent 团队协作和长程任务管理能力的示例，同时为后续的自进化和测试评估提供基础。

## 证据
1. **本地知识库扫描**：提取了与 Claude Code、A2A、MCP 相关的机制，包括上下文管理、记忆、工具调用和钩子系统。
2. **外部协议雷达**：参考了 A2A 协议、MCP（Model Context Protocol）、Claude Code 钩子、LangGraph 持久化等技术文档。
3. **本地 AI 项目扫描**：结合了 `P08_viral_video_agent_lab` 的 A2A 事件驱动设计和 `P03_redis-agent-lab` 的 Redis Streams、锁和记忆机制。
4. **飞书文档**：整合了多个飞书文档中的 agent 设计和实现经验。

## 方案取舍
1. **技术路线**：
   - **事件驱动**：优先实现事件驱动机制，确保 agent 能够常驻并响应事件。
   - **工具调用**：通过工具网关实现技能调用，支持 Skill、Func 和 MCP 协议。
   - **上下文管理**：采用上下文管理机制，支持长程任务的遵循度保证和上下文回放。
   - **记忆机制**：结合 Redis Streams 和本地存储，实现 agent 的记忆和状态管理。
   - **自进化能力**：设计自进化框架，确保 agent 能够在可控范围内进行优化和进化。

2. **实现路径**：
   - **A2A-lite 核心模块**：优先开发事件驱动和工具调用机制，形成 A2A-lite 核心模块。
   - **agent 团队协作**：实现 agent 团队协作机制，支持分工和任务分配。
   - **上下文回放与评估**：设计上下文回放和评估机制，支持任务的回溯和优化。

## 建议路线
1. **第一阶段**：完成 A2A-lite 核心模块开发，实现事件驱动和工具调用机制。
2. **第二阶段**：开发 agent 团队协作机制，支持分工和任务分配。
3. **第三阶段**：实现上下文回放与评估机制，支持任务的回溯和优化。
4. **第四阶段**：设计和实现自进化框架，确保 agent 能够在可控范围内进行优化和进化。

## 待验证
1. **自进化能力**：自进化框架的具体实现细节和可控性需要进一步验证。
2. **上下文回放**：上下文回放的准确性和性能需要通过测试进行验证。
3. **工具调用兼容性**：工具调用机制对不同协议（Skill、Func、MCP）的兼容性需要进一步验证。
