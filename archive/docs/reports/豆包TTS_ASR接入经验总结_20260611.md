# 豆包 TTS/ASR 接入经验总结

**结论：火山引擎豆包语音服务可通过 WebSocket 二进制协议和 HTTP 双接口接入，支持中英混杂合成，但需注意音色校验、引擎切换架构和错误码处理等关键问题。**

## 背景

- **目标**：将豆包 TTS/ASR 作为 Kokoro/FunASR 的云端替代方案用于应用集成，降低对本地 GPU 推理的依赖。
- **触发条件**：需要接入第三方云语音服务，或评估豆包作为备选引擎的可行性。
- **范围**：仅覆盖火山引擎豆包语音服务的接入实现，不涉及其他云服务商。

## 证据

### 1. 协议选择

| 接口 | 协议 | 适用场景 | 推荐度 |
|------|------|----------|--------|
| **ASR v2** | WebSocket 二进制协议 | 流式语音识别，实时性要求高 | ✅ 推荐 |
| **TTS v2** | WebSocket 二进制协议 | 流式合成，低延迟场景 | 可选 |
| **TTS v3** | HTTP RESTful API | 非流式合成，简单集成 | ✅ 推荐 |

> 公开编辑说明：内部连通性与发音实测已删除；接口版本描述保留为历史笔记，接入时需查对应官方文档。

### 2. 音色列表获取

- 豆包 TTS 音色列表需通过火山引擎控制台或 API 文档获取，代码中硬编码了常用音色（如 `zh_female_vv_mars_bigtts`）。
- **注意**：音色名称与 Kokoro 不同，切换引擎时需同步更新音色列表。

### 3. 中英混杂处理

测试集中应包含中英文混写、缩写及专有名词，人工试听后再判断效果；此处不保留内部音频验证结论。

### 4. 错误码处理

| 错误码 | 含义 | 处理方式 |
|--------|------|----------|
| `400` | 请求参数错误 | 检查 API Key、音色名称、文本格式 |
| `401` | 认证失败 | 检查 API Key 是否有效 |
| `403` | 权限不足 | 确认服务已开通 |
| `500` | 服务端错误 | 重试或降级到本地引擎 |

**待验证**：完整错误码列表需参考火山引擎官方文档。

### 5. 引擎切换的通用检查点

引擎选择和音色列表应保持一致；配置应由当前有效配置读取。对不支持的音色给出明确错误，是否允许降级由产品要求决定。

## 方案取舍

| 方案 | 优点 | 缺点 | 推荐 |
|------|------|------|------|
| **仅使用豆包** | 统一引擎，简化维护 | 依赖云端，网络中断时不可用 | ❌ |
| **豆包 + 本地引擎双模式** | 高可用，可切换 | 实现复杂度增加 | ✅ |
| **仅使用本地引擎** | 无网络依赖 | 受限于本地 GPU 性能 | ❌ |

## 建议路线

1. **短期**：验证引擎配置、音色选择与实际请求一致。
2. **中期**：在测试环境切换为豆包引擎，评估领域术语准确率和延迟。
3. **长期**：考虑接入其他云服务商（如阿里云、腾讯云），形成统一的云语音服务抽象层。
