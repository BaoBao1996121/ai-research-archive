# 服务器部署变更影响分析模板

**每次部署前必须逐项回答以下 6 个问题，缺一不可。**

## 适用场景

- 向生产服务器推送代码变更（含 Docker 化服务）
- 涉及 Docker 镜像、前端构建、nginx 配置、文件系统目录的变更

## 触发条件

- 代码已推送至 `origin/main`，准备在服务器上执行 `git pull` 之前
- 或：收到“部署到服务器”任务时

> 以下路径、服务名和端口均为编辑后的教学示例，不对应实际部署。

## 核心步骤

### 1. 变更文件清单

列出本次变更涉及的所有文件（`git diff --name-only origin/main@{1.day.ago} HEAD` 或类似命令的输出）。

### 2. 逐项分析（6 问）

| # | 问题 | 判断依据 | 示例 |
|---|------|----------|------|
| ① | 哪些文件变更？ | `git diff --name-only` 输出 | `server.py`, `Dockerfile`, `web/src/App.js` |
| ② | 属于哪个 Docker 镜像？ | 查看 `docker-compose.prod.yml` 中每个服务的 `build` 或 `image` 字段，对照变更文件路径 | `server.py` → `example-api`；`web/` → 无镜像（需 nginx 托管） |
| ③ | 是否需要重建镜像？ | 检查变更文件是否在 Dockerfile 的 `COPY` 范围内，或 Dockerfile 本身是否变更 | Dockerfile 新增 `COPY /app/data/uploads` → 必须重建 |
| ④ | 是否需要编译前端？ | 检查 `web/` 或类似前端目录是否有变更 | `web/src/` 有变更 → 需 `npm run build` |
| ⑤ | 是否需要改 nginx？ | 检查是否有新端口、新路由、或静态文件托管路径变更 | 新增 8080 端口托管 React build → 需修改 nginx 配置 |
| ⑥ | 是否需要创建新目录？ | 检查是否有新增的挂载目录或数据目录 | `data/uploads` 目录不存在 → 需 `mkdir -p` |

### 3. 生成部署计划

根据 6 问结果，输出以下信息：

- **镜像重建清单**：列出需要重建的镜像名及理由
- **前端构建步骤**：`cd web && npm install && npm run build`
- **nginx 配置变更**：具体修改内容及 reload 命令
- **目录创建命令**：`mkdir -p <dir1> <dir2>`
- **部署命令**：最终执行的 `docker compose up -d` 或 `bash deploy/deploy.sh` 命令

## 证据来源

- `git diff --name-only` 输出
- `docker-compose.prod.yml` 中服务的 `build`/`image`/`volumes` 配置
- `Dockerfile` 中 `COPY` 指令列表
- `nginx` 配置文件（如 `nginx.conf`）
- 前端构建脚本（`package.json` 中的 `build` 命令）

## 验证方式

1. 执行部署计划后，检查服务健康：`curl http://localhost:<port>/health`
2. 检查前端页面是否正常加载：浏览器访问对应 URL
3. 检查 nginx 配置：`sudo nginx -t && sudo systemctl reload nginx`
4. 检查新目录是否存在：`ls -la <dir>`

## 成本 / 风险

| 项目 | 说明 |
|------|------|
| 时间成本 | 完整执行一次约 10-30 分钟（取决于镜像重建和前端编译时间） |
| 风险 | 遗漏任一问题可能导致部署后服务不可用或功能异常 |
| 回滚方案 | 保留上一版本的镜像 tag，或使用 `git reset --hard` 回退代码后重新部署 |

## 下次使用方式

- 每次部署前，将本模板复制到会话中，逐项填写
- 将填写结果作为部署计划的一部分输出
- 部署完成后，将实际执行结果与计划对比，更新模板中的“示例”列

## 速查卡（快速参考）

### 问题
本次部署需要重建镜像吗？需要编译前端吗？需要改 nginx 吗？

### 判断
- **镜像重建**：Dockerfile 变更 或 变更文件在 Dockerfile 的 COPY 范围内 → 是
- **前端编译**：`web/` 或类似前端目录有变更 → 是
- **nginx 修改**：有新端口、新路由、或静态文件托管路径变更 → 是

### 规则
1. 先列变更文件，再逐项回答 6 问
2. 每个“是”都需要在部署计划中给出具体步骤
3. 部署计划必须包含验证步骤

### 例外
- 仅修改文档、测试代码、配置文件（非 Dockerfile 或 nginx）→ 无需重建/编译/改 nginx
- 仅修改 Windows 本地工具（如 `local-tool.pyw`）→ 不部署到服务器
