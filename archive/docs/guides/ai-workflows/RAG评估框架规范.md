# RAG评估框架规范

## 结论
RAG（检索增强生成）评估框架需要建立标准化的评估步骤和对比基准，以确保RAG模型的性能和质量能够被准确衡量和优化。

## 背景
随着RAG模型在生成任务中的广泛应用，如何系统地评估其性能成为一个关键问题。当前评估指标分散，缺乏统一的对比基准，导致评估结果难以横向比较。因此，需要建立一个规范化的评估框架，明确评估步骤和对比基准，以提升评估的准确性和可操作性。

## 证据
1. **关键判断**：在当日复盘中，明确指出RAG评估指标对比基准不明确，需完善评估步骤（见[主题进展-RAG评估框架](#主题进展)）。
2. **技术探索**：通过审查`metrics.js`文件，发现现有指标矩阵使用统一配置，未针对RAG、ASR、TTS等模块进行分域配置（见[技术探索专题-指标矩阵分域](#技术探索专题)）。
3. **代码线索**：`filters.js`和`metrics.js`文件的代码审查结果表明，现有筛选逻辑和指标配置存在优化空间（见[代码探索线索](#代码探索线索)）。

## 方案取舍
1. **对比基准选择**：采用`dev1000`作为对比基准，因其具有广泛的应用基础和较高的行业认可度。
2. **评估步骤设计**：从数据准备、模型运行、指标计算到结果分析，建立完整的评估流程。
3. **指标矩阵分域**：为RAG、ASR、TTS等模块配置独立的指标集，确保评估结果的准确性和可比性。

## 建议路线
1. **明确对比基准**：确定`dev1000`作为RAG评估的对比基准，并在文档中详细说明其适用范围和计算方法。
2. **完善评估步骤**：制定完整的评估流程，包括数据准备、模型运行、指标计算和结果分析。
3. **制定指标矩阵**：为RAG模块配置独立的指标集，确保评估结果的准确性和可比性。
4. **文档规范化**：将评估框架规范文档化，存放在`docs/guides/ai-workflows/`路径下，供团队成员参考和使用。

通过以上措施，可以建立一个规范化、可操作的RAG评估框架，为RAG模型的性能评估和优化提供有力支持。
