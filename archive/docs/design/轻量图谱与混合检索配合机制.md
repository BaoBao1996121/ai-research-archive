# 轻量图谱自动抽取与混合检索配合机制

**轻量图谱不是 ML 模型抽取，而是基于预定义规则从 QA 对提取实体/关系；运行时做路由/候选增补/实体归一，不替代混合检索。**

---

## 一、调研结论

轻量图谱（Light KG）与混合检索（Hybrid Retrieval）是 RAG 管线中两个**互补而非替代**的组件。轻量图谱负责**结构化导航**（实体路由、候选增补、实体归一），混合检索负责**语义匹配**（Dense + BM25 Sparse + RRF 融合 + Rerank）。两者在 RAG 管线中按顺序执行，最终结果合并后由 Rerank 统一排序。

---

## 二、背景

用户反复提问“轻量图谱能否替代混合检索”，表明对两者关系存在理解盲区。实际源码（`utils/rag/pipeline/core.py`）注释明确：“KG 只做路由/候选增补/实体归一”。需要澄清：

- 轻量图谱**不是** ML 模型抽取，而是基于预定义规则从知识库 QA 对中提取实体和关系
- 轻量图谱**不执行**语义检索、向量匹配或排序
- 混合检索是**主检索引擎**，轻量图谱是**辅助增强**

## 四、核心机制详解

### 4.1 轻量图谱自动抽取流程

```
Milvus 导出 → Query Catalog → Light KG → Evidence Cards
```

1. **从 Milvus 导出 QA 对**：`scripts/rebuild_precompiled_rag.py` 调用 `utils/rag/query_catalog.py` 从 Milvus 导出知识库 QA 对
2. **构建 Query Catalog**：将 QA 对组织成可查询的目录结构
3. **提取实体和关系**：`utils/rag/light_kg.py` 基于预定义规则从 QA 对中提取：
   - **实体类型**：产品、型号、问题、模态、特性、应用、问题等
   - **关系类型**：`has_model`、`has_feature`、`used_for`、`solves_problem`、`has_modality` 等
   - **条件边**：特定条件下的关系约束
4. **构建证据卡片**：`utils/rag/evidence_cards.py` 将实体和关系组织成 Evidence Card，供运行时使用

### 4.2 运行时配合流程

```
意图识别 → Query Planner → Hybrid 检索 → KG Evidence 候选增补 → Rerank → Evidence Package → LLM 生成
```

1. **意图识别**：判断用户意图类型和复杂度
2. **Query Planner**：生成检索计划，确定目标集合和检索参数
3. **Hybrid 检索**：`utils/rag/retrieval.py` 执行 Dense + BM25 Sparse + RRF 融合
4. **KG Evidence 候选增补**：`_augment_results_with_kg_evidence()` 将 KG Evidence Card 转为检索候选
5. **去重与合并**：KG 候选与 Hybrid 结果去重
6. **Rerank**：统一排序所有候选
7. **Evidence Package**：构建最终证据包
8. **LLM 生成**：基于证据包生成回答

### 4.3 轻量图谱的具体职责

| 职责 | 说明 | 实现位置 |
|------|------|----------|
| **实体路由** | 根据用户输入中的实体快速定位相关集合 | `utils/rag/intent/routing.py` |
| **候选增补** | 将 KG Evidence Card 转为检索候选，补充 Hybrid 结果 | `_augment_results_with_kg_evidence()` |
| **实体归一** | 统一不同表述的实体名称（如“CT”和“计算机断层扫描”） | `utils/rag/light_kg.py` |
| **关系上下文** | 提供实体间的关系信息，辅助 LLM 理解 | `utils/rag/light_kg.py` |
| **Prompt 片段** | 生成结构化 Prompt 片段，增强 LLM 回答质量 | `utils/rag/light_kg.py` |

### 4.4 混合检索的具体职责

| 职责 | 说明 | 实现位置 |
|------|------|----------|
| **Dense 检索** | 向量语义匹配 | `utils/rag/retrieval.py` |
| **BM25 Sparse 检索** | 关键词精确匹配 | `utils/rag/retrieval.py` |
| **RRF 融合** | 融合 Dense 和 Sparse 结果 | `utils/rag/retrieval.py` |
| **Rerank** | 对融合结果进行重排序 | `utils/rag/retrieval.py` |

## 五、方案取舍

| 方案 | 优点 | 缺点 | 适用场景 |
|------|------|------|----------|
| **仅用混合检索** | 实现简单，语义匹配强 | 缺乏结构化导航，实体识别弱 | 通用问答 |
| **仅用轻量图谱** | 结构化导航强，实体识别准 | 语义匹配弱，无法处理模糊查询 | 结构化查询 |
| **轻量图谱 + 混合检索（当前方案）** | 兼顾语义匹配和结构化导航 | 实现复杂，需要协调两个组件 | 综合问答 |

**当前方案是最优选择**：轻量图谱提供结构化导航和实体归一，混合检索提供语义匹配，两者互补。
