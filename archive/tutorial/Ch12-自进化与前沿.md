## Agent 怎么自己变强？（WHY）

Chapter 7 你学了写 Skill，Chapter 8 你学了评估。整个流程是：**人写 → Agent 执行 → 人评估 → 人改 → Agent 再执行**。

循环里有三个"人"——写、评估、改。Agent 领域最让人兴奋的前沿之一就是：**能不能把这三个"人"也交给 AI？**

换句话说：Agent 不只是执行你给的 Skill，它还能**自己改进自己的 Skill**。

这不是科幻。2026 年已经有多个生产级的自迭代系统。本章带你看看"自己变强的 Agent"是怎么实现的，以及这个领域的前沿还在探索什么。

## 核心概念（WHAT）

### Skill 自迭代的三种粒度

| 粒度 | 描述 | 持久化 | 示例 |
|------|------|:---:|------|
| **实例级** | 当前任务内自我修正 | ❌ | Agent 发现输出有误 → 反思 → 重试 |
| **会话级** | 跨任务积累经验 | 部分 | Agent 在 session memory 中记录"上次这样更好" |
| **技能级** | 修改 SKILL.md 本身 | ✅ | 自动优化 instructions、新增脚本、调整 description |

前两种你已经见过了——Ch2 的 ReAct 循环就是实例级自我修正，Ch6 的 session memory 就是会话级积累。

**技能级自迭代才是真正的"自我进化"**——修改被持久化到 SKILL.md，所有后续任务都受益。

### 全球方案演进：从手动到自动

```
2022 ─── DSP (Demonstrate-Search-Predict)
          └─ 提出"声明式 LM 编程"概念

2023 ─── Reflexion (NeurIPS)     → 语言反馈代替权重更新
     ─── OPRO (Google)           → LLM 作为优化器
     ─── DSPy                    → "自改进管线"编译器

2024 ─── MIPROv2 (EMNLP)        → 多阶段程序联合优化
     ─── TextGrad (Nature 2025)  → 文本梯度自动微分

2025 ─── Anthropic Skill-Creator → 手动 Eval-Driven 迭代
     ─── agent-skills (12K ⭐)   → 结构化 Skill 格式标准化

2026 ─── GEPA (ICLR Oral)       → 进化搜索 + 反思 + Pareto 前沿
     ─── gskill                  → 一条命令自动学习 Skill
     ─── Google ADK adk optimize → 内置优化器
     ─── Hermes Agent            → 闭环学习循环
```

### GEPA：为什么进化搜索赢了

GEPA（Guided Evolution with Pareto Approximation）是 2026 年 ICLR Oral 论文提出的范式，也是当前最有效的自迭代方案。

核心思路：**把 Skill 优化当作进化搜索，而不是梯度下降。**

```
     种群（多个 Skill 版本）
           │
           ▼
    ┌──────────────┐
    │ 评估（跑测试）  │ ← 优胜劣汰：保留效果好的
    └──────┬───────┘
           │
           ▼
    ┌──────────────┐
    │ 反思（分析失败）│ ← LLM 分析"为什么这个版本赢了/输了"
    └──────┬───────┘
           │
           ▼
    ┌──────────────┐
    │ 变异（生成新版）│ ← 基于反思生成改进版本
    └──────┬───────┘
           │
           ▼
    ┌──────────────┐
    │ Pareto 筛选  │ ← 同时优化多个维度（质量 vs 成本 vs 速度）
    └──────────────┘
           │
           ▼
      下一代种群 → 循环...
```

为什么进化搜索比梯度下降更适合优化 Skill？

| 梯度下降 | 进化搜索 |
|---------|---------|
| 需要连续的损失函数 | 只需要"A 比 B 好"的排序 |
| 容易陷入局部最优 | 多个候选同时探索，更容易跳出 |
| 对初始值敏感 | 多种群起步，鲁棒性强 |
| 优化单一目标 | Pareto 前沿自然支持多目标 |

**关键数据**：gskill（基于 GEPA 的工具）能让 Skill 从 24% 基线评分自动进化到 93%——完全无需人工干预。

### Hermes Agent 的闭环学习循环

Hermes Agent（62.8K ⭐）的独特之处在于它把自迭代内置到了整个 Agent 生命周期中：

```
用户使用 Agent
      │
      ▼
  执行任务 → 产生轨迹（trajectory）
      │
      ▼
  好的轨迹 → 提取 Skill → 保存到 Skill 库
  坏的轨迹 → 分析失败原因 → 更新 Skill
      │
      ▼
  下次遇到类似任务 → FTS5 全文检索相关 Skill
      │
      ▼
  使用改进后的 Skill → 更好的轨迹 → ...（循环）
```

这形成了一个**数据飞轮**：使用 → 积累 → 改进 → 更好地使用。

## 动手做（HOW）

### 实验：简化版 Skill 自迭代

用 Python 实现一个最小的自迭代循环：

```python
"""
简化版 Skill 自迭代：生成 → 评估 → 反思 → 改进
基于实验 07_skill_self_iteration.py 的思路简化
"""
import openai
import json

client = openai.OpenAI()

def iterate_skill(initial_skill: str, test_cases: list, max_rounds: int = 3) -> str:
    """
    自迭代循环：让 LLM 改进自己的指令
    """
    current_skill = initial_skill
    
    for round_num in range(max_rounds):
        print(f"\n{'='*50}")
        print(f"迭代轮次 {round_num + 1}/{max_rounds}")
        print(f"{'='*50}")
        
        # Step 1: 用当前 Skill 执行所有测试
        results = []
        for case in test_cases:
            output = execute_with_skill(current_skill, case["input"])
            score = evaluate_output(output, case["expected"], case["criteria"])
            results.append({
                "input": case["input"],
                "output": output,
                "score": score,
                "criteria": case["criteria"],
            })
        
        avg_score = sum(r["score"] for r in results) / len(results)
        print(f"📊 平均分: {avg_score:.1f}/10")
        
        if avg_score >= 9.0:
            print("✅ 质量达标，停止迭代")
            break
        
        # Step 2: 反思 — 分析失败原因
        failures = [r for r in results if r["score"] < 8]
        reflection = reflect_on_failures(current_skill, failures)
        print(f"🔍 反思: {reflection[:200]}...")
        
        # Step 3: 改进 — 基于反思生成新版本
        current_skill = improve_skill(current_skill, reflection)
        print(f"📝 已生成新版 Skill")
    
    return current_skill

def execute_with_skill(skill: str, user_input: str) -> str:
    """用给定 Skill 执行任务"""
    response = client.chat.completions.create(
        model="qwen-plus",
        messages=[
            {"role": "system", "content": skill},
            {"role": "user", "content": user_input},
        ]
    )
    return response.choices[0].message.content

def evaluate_output(output: str, expected: str, criteria: str) -> float:
    """LLM-as-Judge 评估"""
    response = client.chat.completions.create(
        model="qwen-plus",
        messages=[{
            "role": "user",
            "content": f"""评估这个输出的质量(1-10分)。

评估标准: {criteria}
期望方向: {expected}
实际输出: {output}

只返回一个数字(1-10)。"""
        }]
    )
    try:
        return float(response.choices[0].message.content.strip())
    except:
        return 5.0

def reflect_on_failures(skill: str, failures: list) -> str:
    """反思失败案例"""
    failure_text = "\n".join(
        f"输入: {f['input']}\n输出: {f['output'][:200]}\n分数: {f['score']}\n标准: {f['criteria']}"
        for f in failures[:3]
    )
    response = client.chat.completions.create(
        model="qwen-plus",
        messages=[{
            "role": "user",
            "content": f"""分析这个 Skill 为什么在以下测试中表现不好:

当前 Skill:
{skill}

失败案例:
{failure_text}

给出具体的原因分析和改进建议。"""
        }]
    )
    return response.choices[0].message.content

def improve_skill(skill: str, reflection: str) -> str:
    """基于反思改进 Skill"""
    response = client.chat.completions.create(
        model="qwen-plus",
        messages=[{
            "role": "user",
            "content": f"""基于以下反思，改进这个 Skill。

当前 Skill:
{skill}

反思与改进建议:
{reflection}

规则：
- 解释 Why 而非堆砌 MUST
- 不要加不拉分的冗余规则
- 确保改进针对具体的失败模式

输出改进后的完整 Skill 文本。"""
        }]
    )
    return response.choices[0].message.content

# 使用示例
test_cases = [
    {
        "input": "上午开了产品评审会，下午提交了3个PR，晚上修了P1 bug",
        "expected": "按价值排序，突出P1 bug",
        "criteria": "是否按价值而非时间排序？是否识别了风险？",
    },
    {
        "input": "今天写了一天文档",
        "expected": "仍然找到价值，不说'没什么成果'",
        "criteria": "是否正面表述？是否找到了文档工作的价值？",
    },
]

initial_skill = "你是一个日报总结助手。帮用户写日报。"
improved = iterate_skill(initial_skill, test_cases, max_rounds=3)
print(f"\n{'='*50}")
print("最终版 Skill:")
print(improved)
```

### 前沿方向：Agent 领域的三个探索前沿

学完整个教程后，你对 Agent 已经有了从概念到生产的完整认知。以下是当前最活跃的三个探索方向：

| 方向 | 核心问题 | 当前状态 | 代表项目 |
|------|---------|---------|---------|
| **Agent 操作系统** | Agent 能否像 OS 一样管理资源、调度任务、隔离权限？ | 早期但发展快 | Hermes Agent、Claude Code |
| **Agent 间通信协议** | 不同框架的 Agent 怎么互相对话？ | 标准正在形成 | A2A（Google）、MCP（Anthropic） |
| **自主学习闭环** | Agent 能否从使用中自动积累能力？ | 有生产级原型 | gskill、Hermes 闭环、DSPy 编译器 |
| **技能设计模式库** | 不同场景下 Skill 怎么设计最优？ | 已有系统总结 | Google ADK 五大模式 |

#### A2A vs MCP：一句话区分

- **MCP**（Model Context Protocol）= **工具接口标准**——定义 Agent 怎么调用工具（类似 USB 接口）
- **A2A**（Agent-to-Agent）= **Agent 通信标准**——定义 Agent 怎么和另一个 Agent 对话（类似 HTTP 协议）

两者不互斥。一个生产系统里，Agent 用 MCP 调工具，用 A2A 与其他 Agent 协作——就像你用 USB 接外设，用 WiFi 跟同事通信。详见 [A2A协议入门学习指南](../reports/04-%E5%B7%A5%E7%A8%8B%E5%AE%9E%E8%B7%B5/R50_A2A%E5%8D%8F%E8%AE%AE%E5%85%A5%E9%97%A8%E5%AD%A6%E4%B9%A0%E6%8C%87%E5%8D%97.md)。

#### ADK 五大 Skill 设计模式

Google Agent Development Kit（ADK）总结了 Agent Skill 设计的五大模式：单 Agent、顺序 Agent、并行 Agent、循环 Agent、自定义编排。这为 Ch7 的 Skill 工程化提供了更系统的设计框架。详见 [Google ADK五大Agent技能设计模式研究报告](../reports/01-%E7%90%86%E8%AE%BA%E4%B8%8E%E6%9E%B6%E6%9E%84/R06_GoogleADK%E4%BA%94%E5%A4%A7Agent%E6%8A%80%E8%83%BD%E8%AE%BE%E8%AE%A1%E6%A8%A1%E5%BC%8F.md)。

### 思考题

1. **自迭代的停止条件很关键。** 上面的代码用 `avg_score >= 9.0` 做停止条件。如果评估本身不准确（Ch8 讲过讨好偏差），会怎样？
2. **GEPA 用进化搜索同时探索多个 Skill 版本。** 但每个版本都需要跑测试用例来评估——如果你有 100 个测试用例，每代种群 10 个版本，迭代 5 轮，一共需要多少次 LLM 调用？成本多少？
3. **Hermes 的数据飞轮 vs 你在 Ch1 用的 OpenClaw（Hermes 前身）。** 你在 Ch1 的使用过程中，它有没有"变聪明"？为什么？
