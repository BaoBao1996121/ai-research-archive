## 为什么部署很重要？（WHY）

到目前为止，你的 Agent 只能在你自己电脑上的终端里跑。你的同事想用，你得说"克隆我的仓库，装好 Python，配好 API Key，然后跑 `python agent.py`"。

大多数人到这一步就放弃了。

**一个别人用不了的 Agent = 一个不存在的 Agent。** 部署不是"锦上添花"，它是价值传递的最后一公里。

好消息：部署不一定复杂。根据你的用户规模和需求，从"3 分钟加个 WebUI"到"K8s 集群"有 8 个级别，你只需要选适合你当前阶段的。

## 核心概念（WHAT）

### 八级部署光谱

| 级别 | 方案 | 复杂度 | 用户规模 | 适合阶段 |
|:---:|------|:---:|:---:|------|
| L0 | 命令行 / REPL | ⭐ | 1 人 | 自己开发验证 |
| L1 | 本地 WebUI（Gradio/Streamlit） | ⭐⭐ | 1-5 人 | 内部 demo 演示 |
| L2 | 独立 Web 应用（FastAPI） | ⭐⭐⭐ | 10-100 人 | 小型产品 |
| L3 | IM 机器人（飞书/钉钉/Slack） | ⭐⭐⭐ | 10-1000 人 | 企业内部 |
| L4 | Agent 平台托管（Dify/Coze） | ⭐⭐ | 10-10000 人 | 快速上线 |
| L5 | Docker 容器化 | ⭐⭐⭐ | 10-500 人 | 正式产品 |
| L6 | Kubernetes 集群 | ⭐⭐⭐⭐⭐ | 500-∞ | 企业级 |
| L7 | Serverless（云函数） | ⭐⭐⭐⭐ | 10-∞ | 弹性业务 |

### 怎么选？一个简单的决策树

```
你的 Agent 是给谁用的？
├── 就自己
│   └── L0 命令行就够了（你现在就在这个阶段）
│
├── 给团队 5 人以内演示
│   └── L1 Gradio（3 分钟加个 WebUI）
│
├── 给公司几十上百人用
│   ├── 他们有 IM 工具（飞书/钉钉/Slack）？
│   │   └── L3 IM 机器人（嵌入已有工作流）
│   └── 需要独立界面？
│       └── L2 FastAPI + 前端
│
├── 不想管基础设施
│   └── L4 平台托管（Dify/Coze 零运维）
│
└── 要正式上线给外部用户
    ├── 流量稳定 → L5 Docker
    ├── 流量波动大 → L7 Serverless
    └── 需要高可用/大规模 → L6 K8s
```

### 部署的四大核心问题

无论选哪个级别，你都需要回答：

```
┌────────────────┬────────────────┬────────────────┬────────────────┐
│  🔌 接入层      │  🧠 推理层      │  💾 状态层      │  🔒 运维层     │
│  用户怎么交互？ │  LLM 在哪跑？   │  记忆/会话      │  监控/安全     │
│                │                │  怎么保存？     │  怎么保障？    │
├────────────────┼────────────────┼────────────────┼────────────────┤
│ • CLI          │ • 云端 API     │ • 内存(临时)    │ • 日志记录     │
│ • WebUI        │ • 本地模型     │ • 文件系统      │ • API 限流     │
│ • REST API     │ • 自部署推理   │ • Redis         │ • 密钥管理     │
│ • IM Bot       │   (vLLM等)    │ • 数据库        │ • 成本监控     │
└────────────────┴────────────────┴────────────────┴────────────────┘
```

## 动手做（HOW）

### L1: Gradio — 3 分钟加 WebUI

这是"性价比"最高的方案。把 Ch4 的 Agent 包一层 Gradio 界面：

```python
"""
用 Gradio 给你的 Agent 加一个 Web 界面
"""
import gradio as gr
import openai

client = openai.OpenAI()

def agent_chat(message: str, history: list) -> str:
    """
    Gradio 聊天接口：接收用户消息，调用 Agent，返回回复
    """
    # 构建消息历史
    messages = [
        {"role": "system", "content": "你是一个有用的 AI 助手。"},
    ]
    for user_msg, bot_msg in history:
        messages.append({"role": "user", "content": user_msg})
        messages.append({"role": "assistant", "content": bot_msg})
    messages.append({"role": "user", "content": message})
    
    # 调用 LLM（实际中这里是你的 agent_loop）
    response = client.chat.completions.create(
        model="qwen-plus",
        messages=messages,
    )
    return response.choices[0].message.content

# 一行代码启动 WebUI
demo = gr.ChatInterface(
    fn=agent_chat,
    title="🤖 我的 Agent",
    description="基于 Ch4 构建的 Agent — 现在有 WebUI 了！",
)

if __name__ == "__main__":
    demo.launch(share=True)  # share=True 生成公网临时链接
```

```powershell
pip install gradio
python agent_web.py
```

运行后打开 `http://localhost:7860`，你的 Agent 就有了一个可以分享给同事的网页界面。`share=True` 还会生成一个 72 小时有效的公网链接。

### L5: Docker — 标准化交付

当你需要"在任何机器上一键启动"：

```dockerfile
# Dockerfile
FROM python:3.12-slim

WORKDIR /app

COPY requirements.txt .
RUN pip install --no-cache-dir -r requirements.txt

COPY . .

# 不在镜像中硬编码密钥！运行时通过环境变量传入
ENV OPENAI_API_KEY=""
ENV OPENAI_BASE_URL=""

EXPOSE 7860

CMD ["python", "agent_web.py"]
```

```powershell
# 构建并运行
docker build -t my-agent .
docker run -p 7860:7860 -e OPENAI_API_KEY="你的Key" my-agent
```

### L2: FastAPI — 给其他系统调用的 API

当你的 Agent 不是直接面向用户，而是作为其他系统的后端：

```python
"""
Agent 作为 REST API 服务
"""
from fastapi import FastAPI
from pydantic import BaseModel

app = FastAPI(title="Agent API")

class ChatRequest(BaseModel):
    message: str
    session_id: str = "default"

class ChatResponse(BaseModel):
    reply: str
    tokens_used: int

@app.post("/chat", response_model=ChatResponse)
async def chat(req: ChatRequest):
    # 这里调用你的 agent_loop
    reply = agent_loop(req.message)  # Ch4 的函数
    return ChatResponse(reply=reply, tokens_used=0)

# uvicorn agent_api:app --host 0.0.0.0 --port 8000
```

### SDK 集成模式：Agent 作为应用引擎

前面的部署方式都是把 Agent 当作独立服务。但如果你想把 Agent 能力嵌入已有的应用程序呢？

**SDK 模式**让你直接在代码中调用 Agent——不需要部署独立进程、不需要 API 层、不需要网络请求。就像在你的 Python 脚本里导入一个库：

```python
# 用 Claude Agent SDK 在你的应用里嵌入 Agent 能力
from claude_sdk import Agent

agent = Agent(model="claude-sonnet-4-20250514", tools=[search, database])
result = agent("分析上周的用户流失数据")

# result 直接在你的 Python 代码中使用
process_analysis(result)  # 你的业务逻辑
```

**什么时候选 SDK 模式**：
- 你在开发一个产品，Agent 是其中一个模块（不是全部）
- 你需要对 Agent 的行为有精细控制（Ch9 的 Hooks 机制）
- 你需要在同一进程中组合多个 Agent（Ch10 的多 Agent 编排）

详见 [SDK-vs-IDE-vs-CLI三种Agent开发模式对比研究](../reports/04-%E5%B7%A5%E7%A8%8B%E5%AE%9E%E8%B7%B5/R29_SDKvsIDEvsCLI%E4%B8%89%E7%A7%8DAgent%E5%BC%80%E5%8F%91%E6%A8%A1%E5%BC%8F.md) 和 [Claude-Agent-SDK从入门到实战完全指南](../reports/04-%E5%B7%A5%E7%A8%8B%E5%AE%9E%E8%B7%B5/R27_ClaudeAgentSDK%E5%85%A5%E9%97%A8%E5%88%B0%E5%AE%9E%E6%88%98.md)。

### 安全清单

部署时必须检查：

- [ ] **API Key 不在代码里**：通过环境变量或密钥管理服务注入
- [ ] **限流**：防止滥用导致 API 费用爆炸（设置每分钟/每用户的调用上限）
- [ ] **输入验证**：对用户输入做长度和内容过滤
- [ ] **日志**：记录每次调用的输入、输出、Token 消耗（但不记录敏感信息）
- [ ] **成本监控**：设置每日 Token 消耗上限和告警
