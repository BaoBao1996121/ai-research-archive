# 服务启动验证流程

## 触发规则
当服务启动失败，且日志中出现以下错误时触发：
- `ModuleNotFoundError`（模块导入错误）
- `ImportError`（导入失败）
- `DependencyNotInstalledError`（依赖未安装）

## 所需工具
- 启动日志分析工具
- 依赖管理工具（如 pip、conda）
- 模块检查工具（如 Python 的 `importlib`）

## 执行流程
1. **检查依赖安装**
   - 使用依赖管理工具列出已安装依赖
   - 对比 `requirements.txt` 或 `environment.yml` 确认所有依赖已安装
   - 若发现缺失依赖，执行安装命令

2. **验证模块导入**
   - 使用 `importlib` 或手动导入方式检查关键模块
   - 确保所有模块路径正确，无拼写错误
   - 检查虚拟环境是否激活（如适用）

3. **检查环境配置**
   - 确认环境变量配置正确
   - 检查配置文件路径是否正确
   - 确认服务运行环境（如 Python 版本）符合要求

4. **记录日志**
   - 将检查结果记录到启动日志
   - 标记成功或失败状态

## 证据规则
- 启动日志必须包含完整的错误信息
- 依赖安装结果需通过工具验证
- 模块导入检查需提供成功或失败的明确反馈

## 失败模式
- **依赖缺失**：关键依赖未安装导致服务无法启动
- **模块路径错误**：模块路径配置错误导致导入失败
- **环境配置错误**：环境变量或配置文件错误导致服务无法正常运行

## 边界
- 仅适用于服务启动阶段
- 不处理运行时错误
- 不涉及第三方服务的依赖检查
