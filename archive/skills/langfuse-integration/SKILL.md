# Langfuse 集成方案

## 触发规则
当需要提升 LLM 调用的可观测性时，触发本方案。

## 所需工具
- Langfuse SDK
- 装饰器 (`@observe()`)
- 上下文管理器 (`with observe(...):`)

## 执行流程
1. **识别 LLM 调用点**：
   - 扫描代码库，定位所有直接或间接调用 LLM 的位置。
   - 重点关注 `utils/rag/pipeline/llm.py` 和 `data/backend/services/llm_service.py` 等关键文件。

2. **选择集成方式**：
   - 对于同步调用，使用 `@observe()` 装饰器包裹函数。
   - 对于异步或流式调用，使用 `with observe(...):` 上下文管理器。

3. **编写装饰器和上下文管理器**：
   ```python
   from langfuse.client import observe

   @observe()
   def make_llm_call():
       # LLM 调用代码
       pass

   with observe(task_name="llm_call") as observer:
       # 异步或流式调用代码
       pass
   ```

4. **测试集成效果**：
   - 确保可观测性数据（如调用次数、响应时间、模型输出）正确收集。
   - 验证数据在 Langfuse 平台上的展示。

## 证据规则
- **代码路径分析**：通过静态代码分析确认 LLM 调用点。
- **测试结果**：通过单元测试或集成测试验证可观测性数据的正确性。

## 失败模式
- **装饰器未正确应用**：导致部分 LLM 调用未被记录。
- **上下文管理器未正确使用**：导致异步调用的可观测性数据丢失。

## 边界
- 仅适用于基于 HTTP 的 LLM 调用。
- 需要额外处理异步和流式调用场景。
- 可能需要调整代码结构以适应装饰器和上下文管理器的使用。

## 成本/风险
- **开发成本**：需要额外开发时间来集成和测试。
- **风险**：可能引入代码侵入性，影响代码可维护性。

- 直接复制本方案到其他项目或模块，根据具体需求调整代码路径和集成方式。
