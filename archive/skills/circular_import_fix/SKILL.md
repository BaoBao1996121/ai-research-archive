# 循环导入修复方案

## 触发规则
当代码中出现循环导入错误，导致程序启动失败或运行时错误时，触发此修复方案。

## 所需工具
- 代码编辑器（如 VS Code、PyCharm 等）
- 测试框架（如 pytest、unittest 等）
- 代码分析工具（如 pylint、flake8 等）

## 执行流程
1. **识别循环导入**：
   - 查看错误信息，确定循环导入涉及的模块。
   - 使用代码分析工具（如 pylint）或手动检查模块之间的依赖关系。

2. **分析模块依赖**：
   - 确定哪些模块之间存在相互引用。
   - 评估每个模块的功能，找出可以重构或分离的部分。

3. **选择修复方法**：
   - **重构代码**：将共享的代码提取到一个新的模块中，减少依赖关系。
   - **延迟导入**：将导入语句放在函数或类内部，避免模块加载时的循环依赖。
   - **模块级别导入**：将导入语句放在函数内部，而不是模块级别。
   - **删除不必要的导入**：检查并删除不必要的导入语句。

4. **实施修复**：
   - 根据选择的修复方法，修改代码结构。
   - 确保所有导入语句正确，并且没有引入新的循环依赖。

5. **测试修复**：
   - 运行测试用例，确保修复后的代码能够正常启动和运行。
   - 在独立进程中导入模块，验证循环导入问题是否解决。

6. **记录修复方案**：
   - 将修复过程和方法记录下来，形成可复用的技能文档。
   - 更新代码仓库中的相关文档，方便未来参考。

## 证据规则
- **错误信息**：循环导入错误的报错信息，如 `ImportError: cannot import name 'xxx' from 'yyy'`。
- **代码分析结果**：代码分析工具（如 pylint）检测到的循环依赖警告。
- **测试结果**：修复后运行测试用例，确保没有循环导入错误。

## 失败模式
- **修复不彻底**：循环导入问题仍然存在，程序启动失败。
- **引入新问题**：修复过程中引入新的代码错误或功能异常。
- **测试不足**：修复后没有充分测试，导致问题复发。

## 边界
- **适用范围**：适用于 Python 项目中的循环导入问题。
- **模块大小**：适用于小型到中型模块，大型模块可能需要更复杂的重构策略。
- **团队协作**：需要团队成员共同评审和测试修复方案，确保代码质量。

通过以上步骤，可以有效修复循环导入问题，确保代码的稳定性和可维护性。
