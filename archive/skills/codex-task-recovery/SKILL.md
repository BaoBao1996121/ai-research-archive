# 任务接续与恢复规范

## 触发规则
当 Codex 重启后，旧会话的任务无法正常恢复，但任务成果保全时触发。

## 所需工具
- Codex 重启后的旧会话 ID
- Git 仓库检查工具
- 环境变量配置工具

## 执行流程
1. **检查旧任务状态**：
   - 确认旧会话 ID 的工作树是否能正常工作。
   - 检查 Git 仓库健康状态，确认旧任务能否接收新 turn。

2. **接管旧任务**：
   - 如果旧任务无法安全恢复，接管其目标、进度、未完成项和工作区状态。
   - 确保旧任务的工作树数据完整保留。

3. **修复 Git 中文路径转义问题**：
   - 检查并修复 Git 中文路径转义问题，确保路径正确无误。

4. **设置环境变量**：
   - 设置必要的环境变量（如项目解释器路径和依赖搜索路径），解决推送阶段的环境依赖问题。

5. **验证任务接续**：
   - 确保任务成果保全并通过验证。
   - 确认推送阶段成功，远端校验一致。

## 证据规则
- Codex 日志记录任务重启后的状态。
- Git 检查结果确认工作树健康。
- 推送成功日志确认环境依赖问题解决。

## 失败模式
- **任务接续失败**：旧任务无法恢复且工作树损坏。
  - **解决方法**：回滚任务，修复 Git 仓库，重新设置环境变量。

## 边界
- 任务成果必须完整保全。
- Git 仓库必须健康，能够正常执行 Git 操作。
- 环境变量必须正确配置，确保推送阶段顺利进行。
