# 每日会话总结成长飞轮策略

## 一句话结论

每日总结不应该只回答“今天做了什么”，还要把可复用经验沉淀成可再次使用的文档、SOP 或 Skill；默认一份主日报，一张汇报卡片，按需生成详查和资产沉淀。

## 产物分层

| 层级 | 是否每天都有 | 目标读者 | 作用 | 典型位置 |
|---|---|---|---|---|
| 飞书汇报卡片 | 是 | 自己/领导 | 快速知道今天产出、重点、风险、明日计划 | 飞书 IM |
| 主日报 | 是 | 自己 | 完整复盘当天 Copilot/Codex 工作 | `sessions/daily-digest/YYYY-MM-DD.md` |
| Hermes 知识提取 | 是 | 未来的自己/Agent | 抽取技术经验、架构洞察、工作流、踩坑 | `skills/hermes-extracted/YYYY-MM-DD/` |
| 深度调查 | 按需 | 自己/技术决策 | 修正遗漏、串联复杂探索、沉淀推理链 | `skills/hermes-extracted/YYYY-MM-DD/investigation.md` |
| 主题文档/SOP/Skill | 按价值触发 | 团队/未来 Agent | 形成长期可复用资产 | `reports/` 或 `skills/` |

## 是否需要两份报告

默认不是“两份日报”，而是：

1. **主日报**：每天固定生成，回答“今天做了什么、有什么结论、明天接什么”。
2. **详查报告**：只有当当天有复杂技术探索、上下文中断、首轮遗漏、或可形成决策依据时才生成。

这样避免每天制造两份重复报告，同时保留复杂日子的深入分析能力。

## 可沉淀资产判断规则

### 生成主题文档

当内容满足以下任一条件：

- 解释了一个技术系统或架构决策；
- 对多个方案做了取舍；
- 有源码/配置/实验依据；
- 未来可能被团队或自己反复引用。

推荐目录：

- RAG、上下文、知识库：`reports/02-知识管理与上下文/`
- 实验、验证、消融：`reports/03-实验验证/`
- 部署、调试、工程流程：`reports/04-工程实践/`
- 评估、安全、质量：`reports/05-评估与质量/`
- 工具选型、生态调研：`reports/06-工具与生态/`
- 短卡片/速查：`reports/00-速查/`

### 生成 SOP

当内容是重复性操作流程，且后续会再次执行：

- 飞书 QA 数据入库；
- Milvus 备份与清理；
- MCP Server 调试；
- 大文件传输验证；
- 每日总结质量审计。

SOP 必须包含：

- 触发条件；
- 前置条件；
- 操作步骤；
- 验证方式；
- 常见失败模式；
- 回滚或清理。

建议目录：`skills/hermes-extracted/sops/<theme>/`，成熟后迁移到正式 `skills/<skill-name>/`。

### 生成 Skill

当流程不仅可描述，而且适合 Agent 重复执行：

- 有明确触发语；
- 有固定工具链；
- 有验证命令；
- 有错误处理；
- 有边界和权限要求。

成熟 Skill 存放在 `skills/<skill-name>/`。

### 仅保留候选

如果信息有价值但证据不足，先写入 `asset-candidates.md`，标注：

- 候选类型：document / SOP / skill；
- 价值理由；
- 证据来源；
- 推荐路径；
- 下一步动作。

## 每日执行检查

Hermes 每日总结后应自查：

1. 是否覆盖 Copilot 和 Codex 双源？
2. 是否有领导可读的 3-7 条成果摘要？
3. 是否识别了未完成/中断/待继续事项？
4. 是否把可复用内容分类为文档、SOP、Skill 或候选？
5. 是否避免创建散乱文件，而是按主题归档？
6. 是否把不确定结论标注为待验证？
