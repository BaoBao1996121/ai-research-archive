# 详尽会话调查经验 · 2026-06-04

## Context
公开编辑说明：删除私人会话数量、工具调用记录、内部代码与调优案例，仅保留下列会话回顾方法。方法中的预算是历史建议值，并非当前模型限制或实测结论。

## Applicability

本经验适用于**所有使用自动化管线进行每日会话回顾的场景**，特别是当用户同时使用 Hermes Agent（大量工具调用）和 VS Code Copilot Chat 时。

### 三件套：长上下文预算 + 技术探索专题 + 代码探索线索

今后的每日会话调查必须同时执行以下三条，缺一不可：

---

#### ① 长上下文预算

**原则**：宁可塞满也要完整。

- 按目标模型实际上下文容量分配输入预算，并为输出留出空间。
- 不用单条消息硬截断代替完整阅读；长消息分段处理并记录覆盖范围。
- 字符数与 token 数不是固定比例，应按所用模型估算或测量。
- 实现**分卷处理**：当会话总长度超过上限时，按工作区或按时间切片分多次调用 LLM，结果合并

#### ② 技术探索专题

**原则**：捕捉"为什么修改"而非"修改了什么"。

- 从工具调用序列中重建推理链：`read_file` → `patch` → `terminal(测试)` 构成一条探索轨迹
- 对以下高价值主题设置**专题检测标签**，出现即强制独立成段：
  - RAG 相关：意图识别、指代消解、query 改写、rerank、embedding、检索策略
  - 基础设施：MinIO、Milvus、备份策略、Docker 部署
  - Agent 相关：MCP、工具调用链、LLM 路由
- 对每个专题要求输出"问题背景 → 探索路径（含代码路径/函数名） → 形成判断 → 后续动作"四段式
- 专题数量不设上限，有多少写多少

#### ③ 代码探索线索

**原则**：精确到文件和函数签名。

- 对每条代码线索要求：**绝对路径** + 函数/类名（如有） + **今日变化的事实描述** + 证据锚点
- 证据锚点格式：`<file>:<line-range> # <timestamp or reason>`
- 教学示例：记录 `example.py` 的某函数发生了什么变化，并链接对应 diff；不要只写“修改了文件”。
- 代码探索线索应能从后向前追溯：看到线索 → 找到证据 → 理解变更

---

### 补充修正建议（通用管线改进方向）

1. **增设 Hermes Session 读取通道**：如果 Hermes 本地存储了会话记录（包括工具调用参数和结果），读取这些记录比 Copilot 转录更完整
2. **工具调用摘要提取**：对 `read_file` 调用提取被读取的文件路径和关键行号；对 `patch` 调用提取受影响的代码段；对 `terminal` 调用提取命令和输出摘要
3. **差分检测**：对比当天工作区 git diff 与日报内容，如果发现未覆盖的变更文件，标记为"可能遗漏"
4. **回读检验**：日报生成后，让 LLM 重新审视原始会话，回答"日报中是否有 3 处以上明显遗漏？"——自我纠错
