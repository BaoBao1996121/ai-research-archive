# 旧会话接续与成果保全

## 触发规则
当 Codex 重启后，工作树无法正常工作，且需要接续旧会话以恢复任务。

## 所需工具
- 旧会话 ID
- 验证工具（如 `npx repomix`）
- 环境变量设置工具

## 执行流程
1. **接续旧会话**：
   - 使用旧会话 ID 接续任务。
   - 验证旧会话成果是否完整保全。

2. **验证成果**：
   - 执行项目相关测试。
   - 检查项目检查状态。
   - 按项目要求运行质量检查；代码打包工具本身不等于质量验证。

3. **设置环境变量**：
   - 设置必要的环境变量（如项目解释器路径和依赖搜索路径）以解决环境依赖问题。

4. **重新推送代码**：
   - 执行推送命令，确保远端校验一致。

## 证据规则
- 项目相关测试通过日志。
- 项目检查通过记录。
- 质量检查通过日志。
- 远端 SHA 匹配预期。

## 失败模式
- **推送失败**：环境依赖问题未解决，需重新设置环境变量后重新推送。
- **验证失败**：代码质量不达标，需修复后重新验证。

## 边界
- 适用于 Codex 会话重启后的恢复场景。
- 不适用于其他工具或环境的会话恢复。
