# 项目重构目录方案

## 触发规则
- 项目移交前需要提升代码可读性和AI可理解性
- 代码库存在模块边界不清、命名混乱等问题
- 需要为后续开发和维护奠定基础

## 所需工具
- 代码迁移工具（如git、diff工具）
- 测试框架（pytest、node测试工具）
- 文档生成工具（Markdown编辑器）
- 项目管理工具（任务跟踪）

## 执行流程
1. **冻结当前状态**
   - 创建基线文档
   - 固化功能清单和接口契约
   - 创建测试套件
   - 记录当前环境配置

2. **目录迁移**
   - 设计新目录结构
   - 迁移代码模块
   - 更新模块依赖关系
   - 重构文件命名

3. **测试验收**
   - 单元测试
   - 集成测试
   - 文档检查
   - 环境验证

## 证据规则
- 基线冻结：通过测试套件和文档审核
- 目录迁移：通过模块测试和文档更新
- 验收：通过全面测试和文档检查

## 失败模式
- 测试失败：无法通过基线测试
- 文档不完整：关键文档未更新
- 边界不清：模块迁移超出预期范围

## 边界
- 仅限于代码库的结构优化
- 不改变现有功能行为
- 不涉及业务逻辑重构
- 保持与现有环境兼容
