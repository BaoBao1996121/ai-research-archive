# Repomix快照流程规范化

## 触发规则
当需要执行Repomix快照时，检测到代码中存在尾随空格问题。

## 所需工具
- 版本控制系统（如Git）
- 代码检查工具（如grep或IDE的自动格式化工具）

## 执行流程
1. **执行Repomix快照**：按照常规流程执行Repomix快照，确保代码仓库的快照准确无误。
2. **检查尾随空格**：使用代码检查工具扫描代码仓库，识别所有包含尾随空格的文件。
3. **修复尾随空格**：对发现的尾随空格问题进行修复，确保代码质量。
4. **验证修复效果**：重新执行代码检查，确认尾随空格问题已解决。
5. **提交修复结果**：将修复后的代码提交到版本控制系统，确保快照的准确性。

## 证据规则
- 检查代码仓库的历史记录，确认尾随空格问题已被解决。
- 使用代码检查工具生成报告，作为修复成功的证据。

## 失败模式
- 尾随空格问题未完全修复，导致代码质量下降。
- 修复过程中引入新的代码问题，影响代码稳定性。

## 边界
- 适用于所有需要执行Repomix快照的代码仓库。
- 仅适用于检测和修复尾随空格问题，不包括其他代码质量问题。

## 注意事项
- 在修复尾随空格时，确保不会影响代码的功能和可读性。
- 定期执行代码检查，预防尾随空格问题的再次出现。

## 待验证
- 具体使用的代码检查工具是否支持尾随空格检测。
- 修复尾随空格的具体步骤是否适用于所有代码仓库。
