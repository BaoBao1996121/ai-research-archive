# Git Worktree 管理规范

## 触发规则
当需要管理多个分支或工作树时，触发本规范。

## 所需工具
- Git 命令行工具
- 文件管理工具（如 VS Code、PowerShell 等）

## 执行流程
1. **初始化工作树**
   ```bash
   git worktree add <路径> <分支>
   ```
   - 示例：`git worktree add ../example-feature feature/example`

2. **查看现有工作树**
   ```bash
   git worktree list
   ```

3. **切换工作树**
   - 直接进入对应目录：
     ```bash
     cd <路径>
     ```
   - 在 Codex 中切换：
     ```text
     后续都在 <路径> 里操作
     ```

4. **同步工作树**
   - 在目标工作树目录中：
     ```bash
     git pull
     ```

5. **清理不再需要的工作树**
   ```bash
   git worktree remove <路径>
   ```

## 证据规则
- 工作树列表：`git worktree list --porcelain`
- 分支状态：`git branch --show-current`
- 目录结构：文件管理工具查看

## 失败模式
- **分支冲突**：尝试在当前目录 checkout 已被其他工作树占用的分支。
  - 解决方案：打开对应工作树目录。
- **工作树损坏**：工作树目录被意外删除或修改。
  - 解决方案：清理并重新创建工作树。

## 边界
- 适用于需要并行开发多个分支的场景。
- 不适用于单分支开发。
- 工作树数量建议不超过 10 个，以免影响性能。
- 工作树存储路径需避免嵌套过深，建议使用平级目录结构。
