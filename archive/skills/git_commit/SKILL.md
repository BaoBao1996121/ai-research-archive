# 语义checkpoint commit模板

## 触发规则
在完成关键测试、验证或代码生成后，需要创建一个语义明确的checkpoint commit。

## 所需工具
- Git

## 执行流程
1. 检查变更内容，确保所有修改已包含在本次提交中。
2. 编写有意义的提交信息，格式如下：
   ```
   [P10c] <变更描述>
   ```
   例如：
   ```
   [P10c] 修复pytest警告（StarletteDeprecationWarning）
   ```
3. 执行提交命令：
   ```bash
   git commit -m "[P10c] <变更描述>"
   ```

## 证据规则
- 提交信息应清晰描述变更内容。
- 提交应通过相关测试和验证。

## 失败模式
- 提交信息不清晰，无法快速定位变更内容。
- 提交未经测试，导致后续问题。

## 边界
- 适用于关键变更点，如测试通过、代码生成正确等场景。
- 不适用于日常的小幅度修改或调试提交。

## 下次使用方式
在完成关键测试或验证后，按照模板生成语义明确的checkpoint commit。
