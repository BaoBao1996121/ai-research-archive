# TTS 性能优化流程

## 触发规则
当检测到 TTS 输出的首文字与首语音差值较大，或用户反馈 TTS 输出延迟、卡顿时，触发本流程。

> 公开编辑说明：以下工具名是功能占位示例，不表示存在可安装的同名工具；不包含内部性能结论。

## 所需工具
- 性能探针工具（如 `perf-tts`）
- 缓存分析工具（如 `cache-inspector`）
- 配置管理工具（如 `config-validator`）

## 执行流程
### 1. 问题定位
1.1 检查 TTS 输出的首文字与首语音差值，确认是否超过阈值（阈值由场景验收要求确定）。
1.2 使用 `perf-tts` 工具获取当前 TTS 引擎的性能数据，包括延迟、卡顿率和缓存命中率。
1.3 分析 `config/` 目录下的缓存配置文件，确认缓存策略是否合理。

### 2. 性能探针
2.1 使用 `perf-tts` 工具运行性能探针实验，生成性能报告。
2.2 通过 `cache-inspector` 工具分析缓存命中率和缓存失效情况。
2.3 检查 项目已有问题记录 中的缓存优化记录，确认是否存在已知问题。

### 3. 优化实施
3.1 根据性能报告和缓存分析结果，优化缓存策略（如增加缓存容量、调整缓存过期时间）。
3.2 更新 TTS 引擎的配置文件，确保缓存机制生效。
3.3 重新运行性能探针实验，验证优化效果。

## 证据规则
- 性能数据：通过 `perf-tts` 工具获取的延迟、卡顿率和缓存命中率数据。
- 配置文件：`config/` 目录下的缓存配置文件。
- 优化记录：项目已有问题记录 中的缓存优化记录。

## 失败模式
- 性能探针未覆盖关键场景，导致优化效果不明显。
- 缓存优化策略无效，导致性能问题持续存在。
- 配置错误导致性能问题恶化。

## 边界
- 适用于需要测量首语音延迟的 TTS 集成。
- 仅适用于多轮上下文场景下的性能优化。
- 需要人工干预确认性能优化效果。
