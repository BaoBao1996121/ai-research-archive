# RAG 管道优化方法

## 触发规则
当检测到跨产品召回率（group_support_recall@10）低于目标阈值（0.62）时，触发跨产品路由识别优化流程。

## 所需工具
- 代码分析工具（如静态分析器）
- 实验数据平台（如A/B测试框架）
- 数据可视化工具（如Tableau或Power BI）

## 执行流程
1. **分析现有路由识别策略**：
   - 审查当前的路由识别逻辑，识别瓶颈和低效部分。
   - 通过代码分析工具定位关键模块（如`utils/rag/pipeline/core.py`）。

2. **扩展候选产品选择逻辑**：
   - 增加候选产品的选择能力，优化跨产品路由识别策略。
   - 引入新的候选产品选择规则，如基于问题关键词的产品映射。

3. **进行A/B测试**：
   - 在实验环境中部署优化后的路由识别策略。
   - 比较优化前后的召回率、准确率和延迟等指标。

4. **验证和调整**：
   - 分析实验数据，评估优化效果。
   - 根据测试结果调整候选产品选择逻辑，进一步优化召回率。

5. **记录和部署**：
   - 记录优化过程和结果，形成可复用的优化方案。
   - 将优化后的策略部署到生产环境。

## 证据规则
- **实验数据对比**：通过A/B测试对比优化前后的召回率、准确率和延迟等指标。
- **人工审核**：对优化后的结果进行人工审核，确保召回的产品与问题相关。

## 失败模式
- **候选产品选择过多**：可能导致噪声增加，影响召回质量。
- **路由逻辑过于复杂**：可能影响性能，增加延迟。
- **测试结果不显著**：可能需要进一步调整策略。

## 边界
- 适用于多产品展厅场景，处理跨产品路由识别问题。
- 不适用于单产品或特定领域的问题。
